# 과제 2 테스트 기록 — 제출본 서비스(서류 업로드 → 이름 검수 → 회사 사전)

> 2026-10-23: 이 기록은 서류 검수 제품(제출본 2026-10-22)의 것이다. 제품은 TTS 앞단 층으로 전환했지만([ADR-023](adr/ADR-023.md)) 코드가 그대로라 이 기록이 현재 코드의 동작을 설명한다. 기록한 값은 고치지 않는다.

- 이 문서: 제출본(단일 문서 검수 서비스)의 실행 방법과 기능별·예외 테스트 기록이다. 각 절은 그 기능을 넣은 날 실제로 실행한 것만 적었고, 기록한 입력·예상·실제 값은 고치지 않는다. 기능별로 어느 절을 보면 되는지는 아래 요약에 있다.
- 환경: macOS, Python 3.11.15, uv, camel-tools 1.6.0 + calima-msa-r13, Postgres 17(Homebrew, 로컬 소켓 `postgresql+psycopg:///tashkeel`), fastapi 0.156, fastmcp 4.1, mcp 2.3, sqlalchemy 2.1, alembic 1.20. Docker 스모크는 Mac arm64, Docker 29.6, Compose 5.3(6.1절 P-11).
- 자동 테스트: 전체 `uv run pytest -m "not live"` 559개 통과(Postgres 포함, 8.5절 6번). 절마다 쓴 테스트 파일은 그 절에 적었다.
- 화면 캡처: `docs/images/`.

## 제출본 기준 요약

### 실행 방법 (Mac)

```bash
uv sync && uv run camel_data -i morphology-db-msa-r13
cp .env.example .env        # OPENAI_API_KEY를 넣는다. 키 없이 화면만 보려면 LLM_BACKEND=fake
LLM_BACKEND=openai AUTH=disabled uv run tashkeel serve --port 8000    # DB 없이(사전·보관함은 메모리)
# Postgres를 쓰려면: createdb tashkeel 뒤 DATABASE_URL=postgresql+psycopg:///tashkeel ./run.sh
```

화면 `http://127.0.0.1:8000/#/upload`, API 문서 `/docs`, 상태 `/health`. 기본 조건은 M2이고, `REVIEW_CONDITION=C1`이면 EXP-003에서 잰 설정(LLM 한 번)으로 돈다. `run.sh`는 키·포트를 검사하고, `DATABASE_URL`이 있으면 `alembic upgrade head`를 돌린 뒤 서버를 띄워 `/health`를 기다린다. Docker Compose 패키지는 [deploy.md](deploy.md)에 있다.

## 1. 실행 방법 (Mac, 2~4절 기록 때)

1~4절은 단계 1.5 서비스(2026-10-21)의 기록이다. 모델은 가짜 모델(`LLM_BACKEND=fake`)이다. 이때 자동 테스트는 `tests/test_web_api.py` 15개(그중 `db` 마커 1개), `tests/test_mcp.py` 10개(그중 `camel` 마커 2개), `tests/test_graph_fake.py`의 `on_node`·`analyze_tool_factory` 2개였고, 전체 `uv run pytest -m "not live"` 372개 통과·3 skip(묶음 검수 테스트 포함, DATABASE_URL 있음), 골든 160건 변화 없음.

```bash
uv sync && uv run camel_data -i morphology-db-msa-r13
createdb tashkeel                                   # 또는 docker compose up db
cp .env.example .env                                # LLM_BACKEND, DATABASE_URL, USE_MCP_TOOLS를 넣는다
LLM_BACKEND=fake USE_MCP_TOOLS=true DATABASE_URL=postgresql+psycopg:///tashkeel ./run.sh
```

`run.sh`는 키·포트를 검사하고 `alembic upgrade head`를 돌린 뒤 `uv run tashkeel serve`를 띄워 `/health`를 기다린다. 화면 `http://127.0.0.1:8000`, API 문서 `/docs`.

## 4. 하지 않은 것

- 실제 모델(`LLM_BACKEND=openai`) 실행. EXP-002 eval이 같은 API 키로 돌고 있어 끝난 뒤 dev 문서 1개로 1회 실행해 여기에 적는다. → 실행함: 7절(실제 모델로 dev 문서 3회), 8.3·8.6절.
- 분석기 로드 실패 기동 거부: camel DB가 설치된 환경이라 재현하지 않았다. 코드 경로는 `build_runtime` → `thread_safe_analyze()` → `AnalyzerUnavailable(ConfigError)`로 E-5와 같다.
- `docker compose up` 전체 기동. `Dockerfile`·`docker-compose.yml`은 작성만 했고 이미지를 빌드하지 않았다[미확인]. → 6.1 P-11에서 빌드·기동·스모크 PASS.

### 8.4 하지 않은 것

### 8.5 화면 이름 상태를 세 가지로 (2026-10-22)

사용자 결정으로 결과 화면의 이름 색을 다섯(주황 보류, 보라 보관함 제안, 초록 문서 근거 확정, 파랑 사전 확정, 빨강 사전과 문서가 다름)에서 셋(초록 확정, 주황 확인 필요, 빨강 사전과 문서가 다름)으로 줄였다. 화면(`web/static/index.html`)만 바꿨고 API 결과의 상태 값과 검수 로직은 그대로다. 세부 상태(근거가 문서인지 사전인지, 지난 서류 후보가 있는지)는 이름을 누르면 패널 머리에 나온다.
