# 기능, 다음 작업, 위험

- 마지막 업데이트: 2026-10-23 (TTS 전환, [ADR-023](adr/ADR-023.md))
- 서류 검수 제품의 기능 F1~F20·다음 작업·위험은 [보관본](archive/document-review/roadmap.md)에 있다. 이 문서의 기능 번호는 T1~로 새로 시작한다.
- 근거 표기는 [docs/README.md](README.md)와 같다.

## 결론

- 제품은 실시간 아랍어 TTS의 이름 발음 앞단 층이다. 오프라인에서 고객 발음 사전을 만들고(후보 생성 → 근거 검사 → 사람 확정), 실시간에서 사전 조회와 결정적 디아크리타이저로 엔진 형식 텍스트를 낸다.
- **지금은 계획만 있다.** 코드는 서류 검수 제출본이고, 측정값은 없다. 다음 작업의 첫째는 EXP-006(엔진 베이스라인)의 판정 기준·예산을 사용자가 확정하고 실행하는 것이다.
- 서류 검수 경로는 코드만 두고 보류했다.

## 2. 다음 작업

모두 [제안]이고 시작은 사용자가 정한다([scope.md](scope.md) "아직 정하지 않은 것").

1. **EXP-006 사전 등록 확정과 실행.** 판정 기준·예산·엔진 목록·이름 세트(CamelProp 걸프 하위 집합 + 자체 라벨 가능 여부)를 정한다. 자체 라벨러를 구하지 못하면 CamelProp만으로 돌리고 걸프 방언 독법은 재지 않는다고 적는다. 결과로 [architecture.md 4.7절](architecture.md) 매트릭스를 채운다.
2. **디아크리타이저 지연·정확도 소규모 점검.** CATT-EO ONNX, libtashkeel, CAMeL GLF를 CamelProp dev 50개에서 이름 단위 DER과 문장당 ms로 비교한다(LLM 없음, 비용 0). 결과를 T7 선택 근거로.
3. **1단계 착수: 사전 스키마(Alembic 0005)와 후보 생성(T3).** `english_name` NULL 허용, 새 컬럼, `exp001` 필터 확장. 테스트는 CamelProp dev로.
4. **엔진 어댑터 2개(T8)와 G2P(T9) 첫 판.** EXP-006에서 "존중"으로 판정된 엔진부터.
5. **확정 큐(T6)와 피드백 배관.** 확정 출처·이전 값·확정자를 처음부터 기록한다(서류 검수에서 빠져 있던 것).
6. **실시간 API(T10)와 합성 발화 생성기(5.4절)로 지연 측정.**
7. **사업성 검토 재계산.** 보관된 검토([archive/business/](archive/business/feasibility.md))는 서류 검수·KYC 기준이다. 1차 고객 유형(은행·통신사 콜센터 / 정부 / CPaaS)과 가격 단위(통화당·이름당·월정액)를 다시 본다.
8. **서류 검수 코드 유지 여부 결정.** 테스트 559개·골든 160건의 유지 비용과 재사용 모듈의 분리.
