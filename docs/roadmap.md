# 기능, 다음 작업, 위험

- 마지막 업데이트: 2026-10-22 (제출본 기준)
- 이전 계획(마일스톤 M0~M6, API·데이터 모델 초안, 단계별 체크리스트, KYC 묶음 흐름)은 커밋 `d2e7fc9`의 이 문서와 [진행 기록](archive/progress-log.md)에 있다. 기술 스택과 실제 API·DB 표는 [architecture.md](architecture.md) 4.8절에 있다.
- 근거 표기는 [docs/README.md](README.md)와 같다.

## 결론

- 제출본은 단일 문서 검수 서비스다. 파일을 넣으면 이름(사람·회사·기관)마다 근거와 함께 확정 또는 보류를 내고, 사람이 확정한 표기를 회사 사전으로 재사용한다. 기본 경로는 조건 M2(두 agent + 회사 기록 MCP + 회사 문서 보관함 + 코드 중재자)다.
- 측정한 것은 지시문만 준 C1(합성 시험지 엄격 0.9993·안전 1.0)이고, 서비스 기본값 M2는 재지 않았다. 다음 작업의 첫째가 M2 측정이다.
- 서류 묶음 검수, 멀티 에이전트 틀 M1, 분석기 MCP 서버는 코드만 두고 보류했다.

**제외(목표가 아님, [problem-and-goals.md](problem-and-goals.md) 1.2절):** 번역 문장 품질 평가·개선, 제출용 공인 번역 대체, 날짜·숫자·금액 보류, 문자 인식 성능 측정, 한국어 출력.

## 2. 다음 작업 (제출 뒤)

순서는 README "향후 계획"과 같다. 모두 [제안]이고 시작은 사용자가 정한다([scope.md](scope.md) "아직 정하지 않은 것").

1. **M2 측정(EXP-005 [제안], [evaluation.md](evaluation.md) 6.6절).** 합성 시험지 dev에서 C1 대비 하락 여부, "근거가 지난 서류에만 있는" 합성 사례에서 제안 적중률과 이름이 같은 다른 대상을 잘못 제안하는 비율, 코드만 쓰는 보관함 조회(A0)와 비교. 판정 기준은 실행 전에 적는다. 결과가 나쁘면 `REVIEW_CONDITION=C1`로 되돌린다. dev 약 $7 [추정].
2. **외부 MCP 클라이언트용 `/mcp` 공개.** API 키로 고객을 정하고 읽기 도구만 둔다.
3. **TS-005 해결.** M2에서 검증 agent의 전체 이름 항목이 단어별 항목을 덮는 문제([troubleshooting.md](troubleshooting.md)). 중재자에서 겹치는 항목을 짝짓는 방향을 검토한다.
4. **F19 자기 회사 표기 감시.**
5. **OCR 실제 호출 1회와 무료 등급 제한 확인.** 키가 생기면 연결 확인만 한다(성능 측정 아님). 민감 서류용 로컬 백엔드는 요구가 생기면.
6. **Postgres에 사전을 둔 실행과 `docker compose up --build` 재확인.**
7. **중소기업 서류 생성기 v3.** 거래처 계약, 정부 통지, 임대차, 인보이스, 근로계약 유형으로 합성 문서를 다시 만든다. 측정은 사용자 동의 뒤.
8. **사람 확인과 실제 서류 측정.** EXP-003 `errors.csv`(C1~C3 오류 5건과 정답 표본)의 사람 확인, 공개 이중언어 문서(F13)로 측정.
9. **회사 사전 키를 거래처 단위로 나눌지 결정.**
