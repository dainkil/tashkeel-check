# 범위와 단계

- 마지막 업데이트: 2026-10-22 (제출본 기준)
- 절 번호(2절, 3절)는 다른 문서가 인용하므로 그대로 둔다. 문서 지도는 [docs/README.md](README.md). 결정의 경과는 [ADR](adr/README.md)과 [changelog](changelog.md)에 있다.

## 2. 어디까지 왔나

원칙은 처음부터 **기능은 적게, 측정은 많이**였다. 측정 장치를 먼저 만들고, 측정 결과에 따라 제품의 방향을 정했다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 실험 장치 | 같은 그래프에서 LLM에게 보여 주는 것만 바꾸는 조건 C0~C3, EXP-001~003 | 완료. EXP-001 통과(여유 없음), EXP-002 보류(쉬운 시험지), EXP-003 판정 `stop`(지시문만 준 C1이 99% 기준 충족) ([experiments](experiments/README.md)) |
| 1.5 서비스화(과제 2) | 단일 문서 API·화면·Postgres·MCP([ADR-012](adr/ADR-012.md)) | 구현. 제출본의 바탕 |
| 2 서류 묶음 검수 | 같은 대상 ID가 붙은 다른 서류의 영문 칸을 근거로 확정([ADR-018](adr/ADR-018.md)) | 구현한 뒤 보류([ADR-021](adr/ADR-021.md)). 코드·테스트는 남아 있다 |
| 완제품 패키지 | API 키 인증·고객 분리·사용량, Docker Compose, 멀티 에이전트 틀 M1([ADR-019](adr/ADR-019.md)) | 구현 |
| 방향 전환 | 고객을 중소기업 내부 검토용으로, 회사 사전 덧씌움, 파일 업로드·OCR 인터페이스, 두 페이지 화면(ADR-021) | 구현 |
| **제출본** | 서비스 기본 경로를 조건 M2로: 두 agent + 회사 기록 툴(MCP) + 회사 문서 보관함(RAG) + 코드 중재자([ADR-022](adr/ADR-022.md)) | 구현, 정확도 미측정. 2026-10-22 현재 산출물로 제출 확정 |
| 3 멀티 에이전트 비교 | 멀티 에이전트를 단일 에이전트와 같은 지표로 비교 | 하지 않음(EXP-005 [제안]) |

## 3. 범위

### 제출본에 들어간 것

| 영역 | 무엇 | 어떻게 |
| --- | --- | --- |
| 입력 | 서류 파일 하나(`.txt`·`.md`·텍스트 층 있는 `.pdf`, 스캔·이미지는 OCR 백엔드를 켰을 때) 또는 붙여넣은 텍스트 | `POST /v1/reviews/upload`, `POST /v1/reviews`. OCR 백엔드는 교체 가능(기본 `none`, 무료 API `ocrspace`) |
| 다루는 고유명사 | 사람 이름(이름·가문명 포함), 회사·상호, 정부기관·단체 이름. LLM이 `proper_noun` 항목으로 뽑는다 | 이름마다 영문 후보·채택 표기·근거를 내거나 보류. 잘 알려진 지명은 직접 번역한다 |
| 확정 규칙 | 이번 문서 안의 근거(두 agent가 같은 철자를 내고 코드 근거 검사를 통과), 사람이 확정한 회사 사전 | 이 둘 말고는 확정하지 않는다. 보관함과 LLM은 제안만 한다 |
| 문서 밖 근거 | 회사 사전(사람이 확정한 표기), 회사 문서 보관함(이 고객이 전에 올린 서류) | 두 agent가 회사 기록 툴로 찾고, 그래프 뒤 덧씌움이 원문으로 다시 확인해 보인다 |
| 사람 확정 | 화면에서 후보를 누르면 회사 사전에 저장, 다음 서류에서 바로 확정 | `POST /v1/dictionary`. 자동 등록 없음 |
| 화면 | 파일 넣기(`#/upload`)와 결과(`#/result/{id}`). 이름 상태 셋(확정·확인 필요·사전과 문서가 다름) | `web/static/index.html` |
| 서비스 | API 키 인증·고객 분리·사용량, Postgres(없으면 메모리), Docker Compose 패키지 | [deploy.md](deploy.md) |
| 측정 경로 | 조건 C0~C3, EXP-001~003 명령, 골든 테스트 | 같은 그래프를 쓴다. `REVIEW_CONDITION=C1`이면 서비스도 EXP-003에서 잰 설정으로 돈다 |

### 코드만 있고 보류한 것

| 무엇 | 보류 이유 | 위치 |
| --- | --- | --- |
| 서류 묶음 검수(대상 ID 근거, 여권 MRZ 해독, 업로드 초안, 묶음 SSE) | 1순위 고객이 여권·대상 ID 묶음이 없는 중소기업으로 바뀜(ADR-021). M2를 받지 않는다(이름이 같다고 잇지 않는다, ADR-018) | `bundle/`, `/v1/bundles/*`, 화면 `#/bundle` |
| 합성 묶음·KYC 묶음 생성기 | 위와 같다 | `data/bundles.py`, `data/kyc_bundles.py` |
| 멀티 에이전트 틀 M1(순서 실행, C3 입력) | M2가 이 틀을 기본 경로로 넓혔다 | `multi_agent.py`, `MULTI_AGENT=true`일 때만 |
| 분석기 MCP 서버(stdio: `analyze_tokens`·`search_bundle`) | 서비스 기본 경로가 분석기 툴을 쓰지 않는다 | `mcp/server.py`, `USE_MCP_TOOLS` 기본 끔 |
| 묶음 검색 틀(Qdrant 메모리 벡터 검색) | 묶음 검수와 함께 보류. pgvector 이전도 하지 않았다 | `rag/bundle.py`, `ENABLE_BUNDLE_SEARCH` |

### 범위 밖

| 무엇 | 이유 |
| --- | --- |
| 날짜·숫자·금액 보류, 이름 아닌 구간의 최종 판단 | 보류 대상은 고유명사만이다(ADR-021) |
| 문자 인식 성능 측정 | 인식 오류와 독법 오류를 구분해 보고할 수 없어서 재지 않는다(ADR-021). 한계로 적는다 |
| 번역 문장 품질 평가, 공인 번역 대체, 한국어 출력 | 목표가 아니다([1.2절](problem-and-goals.md)) |
| 제품 안의 사람 검토 상태 관리, 실무자 인터뷰, 아랍어 검수자 | 할 수 없다. 추후 과제(ADR-008) |
| 외부 MCP 클라이언트용 `/mcp`, 고객당 여러 사용자·권한, 클라우드 배포·TLS | 미뤘다(ADR-019, ADR-022) |
| 실제 고객 서류 측정 | 데이터가 없다. 결과는 합성 문서 기준으로만 보고한다(G6) |

### 판정 기준

다른 문서가 "scope.md 3절"로 인용하는 실험 판정 기준이다. 지표 정의는 [evaluation.md](evaluation.md) 6.2절(EXP-002)과 6.4절(EXP-003)에 있다.

- **EXP-002 합격선(2026-10-20 사용자 확정, 실행 전 고정):** 세 기준을 모두 넘어야 그 조건이 합격이다. (1) 몰래 정함 비율 0.10 이하, (2) 근거 없는 확정 비율 0.02 이하, (3) 근거 채택 검증 통과율 0.90 이상. C1(지시만)이 합격이면 `stop`(지시만으로 충분). C1이 불합격이고 C2나 C3가 합격하면서 C1이 못 넘은 기준마다 차이의 95% 구간(문서 단위 부트스트랩)이 도구 쪽으로 0을 넘으면 `pass`. 그 밖은 `fail`. C0는 판정에 쓰지 않는다. 코드는 `experiments/exp002.py`의 `PASS_BAR`·`judge`다. 외부 근거가 없는 판단값이다(인터뷰 불가, ADR-008).
- **EXP-003 99% 기준(ADR-017):** 이름 부분마다 안전 정확도와 엄격 정확도가 모두 0.99 이상(점추정)이어야 한다. 판정 구조는 EXP-002와 같다. "서비스 기준 99% 달성" 문구는 한쪽 95% 하한도 0.99 이상일 때만 쓴다. 코드는 `experiments/exp003.py`의 `PASS_BAR`·`judge`·`service_claim`이다.

### 사용자가 확정한 것

지금 유효한 결정만 주제별로 모았다. 뒤집힌 결정은 해당 ADR에 남아 있다.

| 주제 | 결정 | 근거 |
| --- | --- | --- |
| 고객 | 걸프 진출 외국 중소기업의 아랍어 서류 내부 검토. 언어쌍은 아랍어 → 영어, 영어권 최종 사용자, 번역사무소는 고객이 아니다 | [ADR-021](adr/ADR-021.md), [ADR-008](adr/ADR-008.md) |
| 제품 한 줄 | 어떤 문서를 넣어도 고유명사마다 읽기 후보를 근거와 함께 제시하고, 사람이 확정한 것만 회사 사전에 저장해 다음 문서에서 바로 확정한다 | ADR-021 |
| 사람 검수 | 제품에 사람 검수를 넣지 않는다. 인터뷰·사전 감사는 추후 과제 | ADR-008 |
| 기본 경로 | 조건 M2(M1 틀에 회사 기록 툴을 더하고 두 역할을 동시에 돌림). `REVIEW_CONDITION=C1`로 되돌릴 수 있다. 지시문은 p1 | [ADR-022](adr/ADR-022.md), ADR-021 |
| 측정 | M2는 실험 없이 완제품부터 만든다. 실제 모델로는 작동 확인만 한다 | ADR-022 |
| 확정 | 근거 없이 확정하지 않는다. 사전은 사람이 후보를 누를 때만 등록한다. 보관함은 제안만 한다(같은 철자가 다른 대상일 수 있다) | [ADR-010](adr/ADR-010.md), ADR-022 |
| 회사 사전 키 | 고객 + `"*"`(고객 전체) + 정규화 아랍어. 인증을 끈 서버는 고객 `local` | ADR-021 |
| 보관함 | RAG 자료는 이 고객이 전에 올린 서류다. 검수를 마친 업로드·붙여넣기 서류만 넣는다 | ADR-022 |
| 입력 | 파일 업로드를 받고, 스캔·PDF는 무료 OCR API를 쓰되 바꿀 수 있게 인터페이스로 둔다. 인식 성능 실험은 하지 않는다 | ADR-021 |
| 화면 | 두 페이지(파일 넣기, 결과). 이름 색은 셋. 화면 상단 상태 줄은 두지 않는다(`/health`에 있다). 채팅 형태는 쓰지 않는다 | ADR-021, ADR-022, ADR-012 |
| 전달 | Docker Compose 패키지 + API 키 + 고객별 데이터 분리 + 사용량 기록. 클라우드 배포는 하지 않는다 | [ADR-019](adr/ADR-019.md) |
| 저장 | Postgres. SQLite는 쓰지 않는다. pgvector는 아직 쓰지 않는다 | [ADR-011](adr/ADR-011.md), ADR-022 |
| LLM 층 | OpenAI `openai:gpt-6.1-sol`, LangChain `create_agent` + 구조화 출력. 가짜 모델은 명시할 때만. `temperature`는 보내지 않는다(0을 받지 않음 [확인]) | [ADR-006](adr/ADR-006.md), ADR-012 |
| MCP | 회사 기록 서버는 내부 agent만 메모리 전송으로 쓴다. 외부 `/mcp` 공개는 미룬다. 분석기 stdio 서버는 플래그로 끼우되 기본은 끈다 | ADR-022, ADR-012 |
| 묶음 검수 | 같은 대상 여부는 대상 ID로만, 확정은 정확 일치일 때만. 지금은 보류 | ADR-018, ADR-021 |
| 실험 기준 | EXP-001 기준 M5(방언 허용) 50%, 고확신 무근거 확정 기준 확신도 0.8, EXP-002 규모 eval 30개 × 3회, EXP-003 99% 기준. 위 "판정 기준" | ADR-017, [6절](evaluation.md) |
| 제출 | 현재 산출물로 제출한다. M2의 전체 이름·단어별 항목 겹침([TS-005](troubleshooting.md))은 고치지 않고 알려진 한계로 둔다 | 2026-10-22 사용자 결정([changelog](changelog.md)) |

### 아직 정하지 않은 것

- M2를 측정할지(EXP-005 [제안], dev 약 $7 [추정])와, 결과가 C1보다 나쁘면 기본값을 C1로 되돌릴지
- 외부 `/mcp` 공개 시점
- (제출 뒤) TS-005를 어떻게 고칠지: 중재자에서 겹치는 항목을 짝짓거나 버림 / 지시문에서 단어 단위를 강제 / 화면에서 단어별 항목을 우선
- 회사 사전 키를 거래처 단위로 나눌지(지금은 고객 전체라 같은 철자의 다른 대상을 잘못 확정할 수 있다)
- OCR 백엔드를 무료 API(제3자 전송)로 둘지, 로컬 백엔드를 만들지
- 실제 서류로 다시 잴지(공개 이중언어 문서 후보의 공개 여부·이용 조건 [미확인])
- EXP-002 나머지 240회를 재개할지(쉬운 시험지라 조건 차이를 가르지 못한다)
- 묶음 검수를 다시 열 경우: 서류 종류별 우선순위, 대상 ID 없는 묶음에 이름 기반 연결을 제안으로 보일지(ADR-018 재검토 조건)
- 보관한 사업성 검토의 수치를 지금 구조로 다시 계산할지, 경제성의 기본 가정(급여 있는 2명 / 대학생 팀)
- LangSmith 키 교체(지금 키는 401로 거부된다), `uv run pre-commit install`로 커밋 훅을 켤지
