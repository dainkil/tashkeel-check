# 범위와 단계

- 마지막 업데이트: 2026-10-23 (TTS 전환, [ADR-023](adr/ADR-023.md))
- 서류 검수 제품의 범위·단계·판정 기준은 [보관본](archive/document-review/scope.md)에 있다. 문서 지도는 [docs/README.md](README.md). 결정의 경과는 [ADR](adr/README.md)과 [changelog](changelog.md).

## 2. 어디까지 왔나

원칙은 그대로 **기능은 적게, 측정은 많이**다. 서류 검수에서는 측정 장치를 먼저 만들고 결과(EXP-003 `stop`)에 따라 제품을 좁혔다. TTS에서도 엔진 베이스라인(EXP-006)을 먼저 재고, 그 수치가 앞단 층의 가치를 보이면 만든다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 서류 검수(2026-10-13 ~ 10-22) | 조건 C0~C3 실험 장치, EXP-001~003, 서비스화, 묶음 검수, 완제품 패키지, M2 기본 경로. 제출본 확정 | 완료, 보관([archive/document-review/](archive/document-review/)). 코드·테스트 559개·골든 160건은 그대로 |
| 전환 조사(2026-10-23) | 서류 검수 품질 방향 조사 → TTS 전환 결정. 아랍어 TTS·이름 발음·실시간 파이프라인 문헌 조사 | 완료([research/](research/tts-literature.md)) |
| **0단계 전환 기록·측정 설계** | ADR-023, 기준 문서 재작성, EXP-006 사전 등록 | **이 문서 시점: 문서만 완료. EXP-006 미실행** |
| 1단계 오프라인 발음 사전 | 후보 생성, 근거 검사, 확정 큐, 사전 스키마, 엔진 출력 변환 | 계획 [제안] |
| 2단계 실시간 경로 | `/v1/pronounce`, 확신 신호, 사후 확정 루프, 보안·레지던시 | 계획 [제안] |
| 3단계 측정 상시화 | 회귀 스위트, 운영 표본 청취, 엔진 매트릭스 갱신 | 계획 [제안] |

## 3. 범위

### 들어가는 것 [제안]

| 영역 | 무엇 | 어떻게 |
| --- | --- | --- |
| 입력 | (오프라인) 이름 목록: 아랍어 표기 + 선택으로 라틴 표기·고객 ID·역할·녹음. (실시간) 말할 텍스트 한 문장~한 턴 + 고객 + 엔진 | CSV·API, `POST /v1/pronounce` |
| 다루는 고유명사 | 사람 이름(이름·가문명 포함), 회사·기관 이름, 지명 | 사전 키 조회 + 규칙·경량 NER |
| 독법 후보 | 고객 사전, CAMeL 분석(격어미·발음 표기 보존), CATT, LLM 디아크리타이저(자음 골격 검사), 라틴 표기 역음역 필터 | 오프라인만. 후보마다 출처 |
| 확정 규칙 | 사람 확정, 본인 녹음 정렬 통과, 라틴 표기 일치 중 하나. 디아크리타이저·LLM은 기본 독법일 뿐 | 코드가 막는다 |
| 실시간 출력 | 사전 적중 high / 분석기 단일 독법·라틴 일치 후보 medium / 디아크리타이저만 low. 엔진 형식(디아크리틱스 텍스트, IPA/X-SAMPA phoneme, 사전 항목, `customPronunciations`)으로 치환 | LLM 없음, p95 ≤ 50ms [제안] |
| 엔진 어댑터 | Azure, Polly, Google, ElevenLabs, 디아크리틱스 텍스트만 받는 엔진 1개(OpenAI 또는 오픈 모델) | 지원 매트릭스는 EXP-006으로 채움 |
| 사후 확정 | 저확신 발화 큐, 합성해 들려주고 고르기, 직접 입력, 녹음 | 확정 출처·이전 값·확정자 기록 |
| 서비스 | API 키 인증·고객 분리·사용량(기존), Postgres(기존 표 + 사전 컬럼 추가), Docker Compose(기존) | 기존 `web/`·`deploy.md` 위에 |
| 측정 | EXP-006 엔진 베이스라인, 후보 포함률, 지연, 회귀 스위트 | [evaluation.md](evaluation.md) |

### 코드만 있고 보류한 것

| 무엇 | 보류 이유 | 위치 |

### 범위 밖

| 무엇 | 이유 |
| --- | --- |
| TTS 모델 학습·파인튜닝, 음성 복제 | 사용자 결정(앞단 층만). 걸프 방언 TTS 데이터가 얇고 GPU·평가 인력이 필요하다 |
| 음성 자연성(MOS) 평가·개선 | 목표가 아니다([1.2절](problem-and-goals.md)). MOS는 이름 정확도를 재지 못한다(Beyond Naturalness 2026 [문헌○]) |
| STT·대화 관리·LLM 응답 생성 | 입력은 말할 텍스트다. 음성 에이전트 프레임워크(LiveKit·Pipecat 등)의 TTS 앞 노드에 끼운다 |
| 숫자·날짜·금액·약어 정규화 | 엔진 내장·NeMo 정규화기에 맡긴다 |
| 사전 제작 음성 편집 화면 | 2차. 같은 사전을 쓰는 하위 경로로 남긴다 |
| 고객당 여러 사용자·권한, 클라우드 배포·TLS | 미뤘다(ADR-019 유지) |
| 실제 고객 발화·녹음 측정 | 데이터가 없다. 공개 이름 벤치와 자체 라벨로만 잰다(G6) |

### 판정 기준

EXP-006의 판정 기준은 실행 전에 [EXP-006 사전 등록](experiments/EXP-006.md)에 고정한다(지금은 [제안]). 지표 정의는 [evaluation.md](evaluation.md). 서류 검수 때의 판정 기준(EXP-002 합격선, EXP-003 99% 기준)은 [보관본](archive/document-review/scope.md)에 있다.

### 아직 정하지 않은 것

- EXP-006 판정 기준과 예산(엔진 4~5개 × 입력 형식 3 × 이름 200개, 청취자 2인)
- 1차 엔진(Azure ar-SA / Polly ar-AE / Google ar-XA / ElevenLabs / 오픈 모델 중)과 1차 로케일(사우디·UAE)
- 지연 목표 수치(제안 p95 50ms)
- 녹음 수집 여부와 동의 절차. 어려우면 근거를 라틴 표기·사람 확정으로 줄인다
- 1차 고객 유형(은행·통신사 콜센터 / 정부 서비스 / CPaaS)과 사업성 검토를 다시 할지([보관 자료](archive/business/feasibility.md)는 서류 검수 기준)
- 걸프 방언 독법과 MSA 독법의 기본값
- 디아크리타이저 선택(CATT-EO ONNX / libtashkeel / CAMeL GLF)과 라이선스 확인
- 서류 검수 코드를 언제까지 유지할지(테스트 559개·골든 160건의 유지 비용)
- LangSmith 키 교체, pre-commit 훅(서류 검수 때부터 미정)
