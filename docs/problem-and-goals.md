# 정의와 목표

- 마지막 업데이트: 2026-10-23 (TTS 전환, [ADR-023](adr/ADR-023.md))
- 서류 검수 제품(2026-10-22 제출본)의 정의·목표는 [보관본](archive/document-review/problem-and-goals.md)에 있다. 절 번호는 새로 시작한다(1.1~1.4). 문서 지도는 [docs/README.md](README.md).

> **정의:** 아랍어 음성 에이전트(콜센터 봇·대화형 에이전트·IVR)가 말할 텍스트에서 고유명사(사람·회사·지명)마다 올바른 독법을 근거와 함께 정해 TTS 엔진에 넘기는 앞단 층. 근거(고객 발음 사전, 본인 녹음, 등록 서류의 라틴 표기, 사람 확정)가 있으면 그 독법을 쓰고, 없으면 기본 독법을 내보내되 낮은 확신으로 표시해 사후 확정 큐에 넣는다. 사람이 확정한 발음은 고객 발음 사전에 쌓여 다음 발화부터 바로 쓰인다.

TTS 엔진이 아니다. 제품이 약속하는 것은 "자연스러운 음성"이 아니라 "이름을 어떻게 읽을지 정한 자리를 빠뜨리지 않고, 근거와 확신을 함께 넘기는 것"이다.

## 1.1 해결하려는 문제

**한 문장:** 아랍어 TTS는 단모음이 없는 텍스트에서 발음을 추측해 읽는데, 고유명사에서 가장 자주 틀리고, 틀렸다는 사실이 운영자에게도 듣는 사람에게도 보이지 않는다.

문제는 세 층으로 쌓여 있다.

| 층 | 내용 | 근거 |
| --- | --- | --- |
| 언어 | 아랍어는 단모음을 적지 않아 같은 철자에 여러 독법이 있다(مسلم은 Muslim일 수도 Musallam일 수도 있다). 본문 단어는 문맥과 빈도로 대부분 풀리지만 고유명사는 문맥이 없고 빈도가 낮다 | 디아크리타이저 오류가 고유명사·외래어에 집중(Sadeed 2025), GPT-4o가 영어 표기를 함께 받고도 고유명사 디아크리틱스 73%(NYUAD CamelProp 2025) [문헌○] |
| 업무 | 이름을 틀리게 부르는 것은 신뢰 비용이다. 콜센터·헬스케어에서 이름 오발음이 고객 경험과 회피 행동으로 이어진다는 보고가 있다. 걸프 인명은 방언 발음(ق→g/j)과 가문별 관행이 있어 표준 독법 하나로 정할 수 없다 | NameCoach 설문·Kaiser 사례(일화 수준), PCGN 걸프 지명 자료 [문헌○]. 걸프 인명 발음 선호 연구는 없다 [미확인] |
| 도구 | TTS 엔진은 내부 디아크리타이저로 하나를 정해 읽고, 그 선택을 표시하지 않는다. 최신 오픈 엔진은 디아크리틱스 입력 없이 합성하는 쪽으로 간다. 발음 제어 수단(SSML `<phoneme>`, 사전)은 엔진·모델·로케일마다 지원이 다르고, 미지원이면 조용히 무시되는 경우가 있다 | Habibi 2026, Azure·Polly·Google·ElevenLabs 문서 [문헌○]. 서류 검수에서 확인한 "모호성 은폐"와 같은 현상 |

**누구의 문제인가:** 사우디·UAE에서 아랍어 음성 봇·IVR을 운영하는 은행·통신사·정부 서비스와 이들에게 음성 에이전트를 공급하는 CPaaS·시스템 통합사. 고객 이름(CRM), 거래처·기관 이름, 지명을 매 통화 읽는다.

- 대상이 아닌 사람: 아랍어 TTS 엔진 개발사(엔진 자체를 만들지 않는다), 오디오북·뉴스 낭독(사전 제작 음성은 2차), 학습 데이터 검수 팀(옛 계획, ADR-001).

**지금 있는 수단으로 안 되는 이유:**

| 수단 | 왜 부족한가 |
| --- | --- |
| 엔진 내장 디아크리타이저 | 고유명사에서 가장 약하고, 어느 이름을 추측했는지 알려 주지 않는다. 고객별 발음 기록이 없다 |
| 엔진 사전·SSML phoneme | 지원이 엔진·모델·로케일마다 다르다(Azure ar-AE는 phoneme 사전 미지원, ElevenLabs는 모델별, Google은 Chirp 3 HD만, 스트리밍 모드는 SSML 불가). 발음을 "무엇으로" 넣을지 정해 주는 것이 없다 |
| 이름 발음 제품(NameCoach·Namedrop·NameShouts) | 영어 중심, 녹음 저장·재생이 주된 기능이다. 아랍어 디아크리틱스·음소 변환과 엔진 출력이 없다 |
| LLM에게 디아크리틱스 요청 | 큰 호스팅 LLM은 문장 디아크리틱스에서 전용 모델보다 낫지만(MBZUAI 2026) 고유명사는 73%이고, 환각으로 자음을 바꾸며, 실시간 지연 예산(수십 ms)에 들어오지 않는다 |

## 1.2 서비스 목표

핵심 약속은 **"읽을 때 선택이 있었던 이름을 빠뜨리지 않고, 근거와 확신을 함께 넘긴다"**다. 보증의 세기는 "모든 이름을 맞게 읽는다"가 아니라 "어느 이름이 확정이고 어느 이름이 추측인지 안다"다. 목표마다 [evaluation.md](evaluation.md)의 지표를 붙이고, 상태는 기록된 결과만 쓴다. **지금은 어느 목표도 측정하지 않았다.**

| 번호 | 목표 | 지표 | 판정 기준 | 상태 |
| --- | --- | --- | --- | --- |
| G1 | **드러낸다.** 발화 텍스트의 고유명사를 빠뜨리지 않고 독법과 확신 등급을 붙인다 | 이름 탐지 재현율·정밀도, 확신 등급 누락 수 | 재현율 기준값은 EXP-006 뒤 확정 [미정] | 미측정 |
| G2 | **근거 없이 확정하지 않는다.** 고객 발음 사전에 들어가는 독법은 사람 확정, 본인 녹음 정렬, 등록 서류·CRM 라틴 표기 일치 중 하나의 근거가 있을 때만 | 근거 없는 사전 등록 수, 자음 골격 변경 수 | 둘 다 0. 코드가 막는다 | 미측정(규칙만 정함) |
| G3 | **전부 저확신으로 도망가지 않는다.** 근거가 있으면 high로 내보내고, 사전 적중률을 보고한다 | 확신 등급 분포, 커버리지(high 비율), 사전 적중률 | 운영 데이터가 생기면 기준값 확정 [미정] | 미측정 |
| G4 | **엔진 단독보다 낫다.** 같은 엔진에서 앞단 층을 거친 발화의 이름 발음 오류율이 거치지 않은 것보다 낮다 | 이름 단위 발음 오류율 차이(사람 청취, 엔진·입력 형식별) | EXP-006 사전 등록 기준(실행 전 고정) | 미측정(EXP-006 [제안]) |
| G5 | **실시간 흐름에 맞는 출력.** 엔진이 받는 형식(디아크리틱스 텍스트, IPA/X-SAMPA, 사전 항목)으로 내보내고, 지연 예산 안에 들며, 저확신 발화는 사후 확정 큐로 간다 | p50/p95 지연, 엔진별 왕복 성공률, 큐 처리율 | p95 ≤ 50ms(이름 든 문장 1개) [제안] | 미측정 |
| G6 | **측정한 범위에서만 약속한다.** 공개 이름 벤치(CamelProp·Wikidata 걸프 인명), 자체 라벨, 운영 표본으로 잰 값만 말하고 엔진·방언·고객을 넘어 일반화하지 않는다 | 실행마다 데이터 범위·엔진 버전·사전 버전 기록 | 기록 없는 결과는 보고하지 않는다 | 지킨다 |
| G7 | **이름 발음 정확도 기준값.** 사용자가 정할 서비스 요구 | 이름 단위 발음 오류율(사람 청취 2인) | EXP-006 결과를 본 뒤 사용자 확정 [미정]. 사람 간 디아크리틱스 불일치(WER 1.6~5.6%, Bouamor 2015 [문헌○])를 넘는 정확도는 약속하지 않는다 | 미정 |

**목표가 아닌 것:**

- TTS 음성의 자연성(MOS)을 높이거나 평가하는 것
- TTS 모델을 만들거나 파인튜닝하는 것(사용자 결정, ADR-023)
- 숫자·날짜·금액·약어의 읽기 정규화(기존 엔진·NeMo 정규화기에 맡긴다)
- 음성 인식(STT)·대화 관리. 입력은 말할 텍스트다
- 사전 제작 음성 편집 화면(2차, 같은 사전을 쓰는 하위 경로)

## 1.3 실험으로 답할 질문

| ID | 질문 | 데이터 | 상태 |
| --- | --- | --- | --- |
| Q1 | 상용·오픈 엔진은 걸프 인명을 얼마나 틀리게 읽는가 | CamelProp 걸프 인명 + 자체 라벨 200개 | EXP-006 [제안], 미실행 |
| Q2 | 디아크리틱스를 붙여 주면 얼마나 고쳐지는가. 엔진이 입력 디아크리틱스를 존중하는가 | 같은 데이터, 엔진 × 입력 형식 | EXP-006 |
| Q3 | phoneme(IPA/X-SAMPA)·사전을 주면 더 고쳐지는가. 어느 엔진·모델·로케일이 실제로 받는가 | 같은 데이터 | EXP-006 |
| Q4 | 후보 생성(분석기·CATT·LLM·라틴 표기 역음역)의 후보에 정답 독법이 드는 비율은 얼마인가 | CamelProp | 1단계 [제안] |
| Q5 | 실시간 경로가 지연 예산 안에 드는가 | 합성 발화 | 2단계 [제안] |

서류 검수 때의 질문 Q0~Q3(형태소 분석기, 지시문)과 답은 [보관본](archive/document-review/problem-and-goals.md)에 있다. 그 결과 중 이번에 쓰는 것은 "실제 걸프 인명의 36.9%는 CAMeL 분석이 0개"(EXP-001)와 "모델이 모름을 판단하게 두면 안 된다"(설계 원칙)다.

## 1.4 요구사항

### 결론

제품은 두 경로다. 오프라인 경로는 이름 목록(CRM·등록 서류·녹음)에서 독법 후보를 만들고 근거를 검사해 사람이 확정하면 고객 발음 사전에 넣는다. 실시간 경로는 발화 텍스트를 받아 사전을 조회하고, 없으면 결정적 디아크리타이저의 기본 독법에 낮은 확신을 붙여 엔진 형식으로 치환한다. 비기능 요구는 실시간 경로에 LLM·난수가 없을 것, 확정·검증은 코드가 할 것, 고객 데이터가 섞이지 않을 것, 녹음은 역내에 동의와 함께 둘 것이다.

### 기능 요구사항 [제안]

| ID | 요구사항 | 경로 |
| --- | --- | --- |
| FR1 | 이름 목록을 받는다(CSV·API: 아랍어 표기, 선택으로 라틴 표기·고객 ID·역할·녹음 참조) | 오프라인 |
| FR2 | 이름마다 독법 후보를 만든다: 고객 사전, CAMeL 분석(격어미·발음 표기 보존), CATT, LLM 디아크리타이저(자음 골격 검사), 라틴 표기 역음역 필터. 후보마다 출처를 붙인다 | 오프라인 |
| FR3 | 근거를 검사한다: (a) 라틴 표기와 후보 로마자의 일치, (b) 본인 녹음이 있으면 격자 제약 정렬 점수·마진, (c) 사람 확정. 근거 종류와 점수를 기록한다 | 오프라인 |
| FR4 | 확정 큐: 후보를 엔진으로 합성해 들려주고 고르기, 디아크리틱스 직접 입력, 녹음 업로드. 확정 출처·이전 값·확정자·시각을 기록한다 | 오프라인 |
| FR5 | 고객 발음 사전: 키 `(customer_id, entity_id, arabic_key)`, 값 `pronunciation`(디아크리틱스 아랍어)·`phonemes`(IPA)·`source`·엔진별 덮어쓰기. 등록·목록·취소 API. 다른 고객의 사전은 보지 않는다 | 공통 |
| FR6 | `POST /v1/pronounce`: 발화 텍스트 + 고객 + 엔진을 받아 고유명사를 탐지하고, 사전 적중은 확정 독법(high), 미적중은 디아크리타이저 1위 + 마진(medium/low)으로 엔진 형식 텍스트를 돌려준다. LLM 호출 없음 | 실시간 |
| FR7 | 엔진 어댑터: Azure(IPA, ar-SA 사전), Polly(IPA/X-SAMPA, ar-AE), Google(Chirp 3 HD `customPronunciations`), ElevenLabs(alias 또는 v4 인라인 IPA), 디아크리틱스 텍스트만 받는 엔진(OpenAI·오픈 모델). 엔진·모델별 지원 매트릭스를 설정으로 두고 미지원이면 폴백한다 | 실시간 |
| FR8 | 발화 로그: 이름·독법·확신·엔진·사전 버전·지연. 저확신 발화는 사후 확정 큐로 | 실시간 |
| FR9 | 통화 뒤 확정 루프: 상담원 또는 고객(IVR 확인 문장)이 저확신 이름의 독법을 확정하면 사전에 들어간다 | 오프라인 |
| FR10 | 측정 경로: 엔진 × 입력 형식 조건을 설정만으로 바꿔 같은 이름 세트를 합성하고, 청취 평가표·ASR 왕복·강제 정렬 결과를 기록한다 | 실험 |

| NFR9 | 비용 통제: 실제 엔진·LLM 호출이 드는 실험은 명시적으로 동의해야 돈다 |
| NFR10 | 라이선스: CAMeL 기본 DB(GPL v2)는 측정과 오프라인 후보 생성에만 쓴다(ADR-005). 실시간 경로의 디아크리타이저는 Apache-2.0·MIT 것(CATT, libtashkeel)을 우선한다 |

### 범위 밖

TTS 모델 학습·파인튜닝, 음성 자연성 평가, STT·대화 관리, 숫자·날짜 정규화, 사전 제작 음성 편집 화면(2차), 고객당 여러 사용자·권한, 클라우드 배포. 서류 검수(업로드·영문 표기·보관함)는 코드만 있고 보류다([scope.md](scope.md)).

### 가정과 확인하지 않은 것

- 엔진이 입력 디아크리틱스를 존중한다고 가정하지 않는다. EXP-006에서 엔진마다 잰다.
- 결정적 디아크리타이저(CATT-EO ONNX·libtashkeel·CAMeL GLF)가 이름 한 구간에서 20~50ms 안에 든다 [가설]. 어느 논문도 문장당 지연을 보고하지 않아 직접 잰다.
- 라틴 표기에서 모음을 역추론하는 규칙의 정확도 [미확인]. e/o·장모음·shadda·인두음 정보가 라틴 표기에 없어 상한이 있다.
- 걸프 방언 독법(ق→g)과 MSA 독법 중 고객이 어느 쪽을 원하는지 [미확인]. 설정으로 두고 측정한다.
- 고객 이름 녹음 수집이 PDPL·동의 절차로 가능한지 [미확인]. 어려우면 근거를 라틴 표기·사람 확정 둘로 줄인다(ADR-023 재검토 조건).
