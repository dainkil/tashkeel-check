# 정의와 목표

- 기준: 분할 전 `PROJECT_PLAN.md` 1절과 `docs/요구사항-분석.md`(2026-10-13). 절 번호는 분할 전 번호를 그대로 둔다(다른 문서의 "N.M절" 참조가 이 번호를 가리킨다). 문서 지도는 [docs/README.md](README.md).
- 마지막 업데이트: 2026-10-21


> **정의:** 아랍어를 못 읽는데 아랍어 문서에 책임을 지는 사람을 위한 검수 도구. 아랍어 → 영어 번역에서 독법이나 표기가 갈리는 구간, 특히 고유명사와 짧은 필드를 드러내고, 근거 없이 확정하지 않는다.

번역기가 아니다. 제품이 약속하는 것은 "정확한 번역"이 아니라 "모호 구간을 얼마나 잡아내는가"다. 사업 판단과 시장·경제성 추산은 [docs/business/feasibility.md](business/feasibility.md)에 있다.

## 1.1 해결하려는 문제

**한 문장:** 아랍어를 못 읽는 사람이 아랍어 서류에 책임을 질 때, 번역이 어디에서 하나를 "골랐는지" 알 수 없다. 특히 이름이 신분증·등기 표기와 달라지면 거래나 등록이 막히는데, 고른 자리가 있었다는 사실 자체가 독자에게 보이지 않는다.

문제는 세 층으로 쌓여 있다. 어느 한 층만 풀어서는 해결되지 않는다.

| 층 | 내용 | 근거 |
| --- | --- | --- |
| 언어 | 아랍어는 단모음을 생략해서 같은 철자에 여러 독법이 생긴다. 문맥이 있는 본문은 최신 LLM이 대부분 풀 것으로 본다. 문맥으로 풀리지 않는 곳은 인명·회사명·지명과 표의 셀, 서명란 같은 짧은 필드다 | [가설, 미측정] |
| 업무 | 서류의 이름 표기는 아랍어 실력이 아니라 외부 근거로 확정된다. ADGM 공증 안내는 위임장의 이름을 UAE 거주자는 Emirates ID, 비거주자는 여권에 적힌 대로 쓰라고 한다. 사우디 중앙은행은 이카마의 아랍어·영문 이름이 맞지 않으면 거래를 허용하지 않는다. 같은 아랍어 이름이 여러 로마자로 쓰인다. Wikidata에서 سعيد رشيد القبيسي의 레이블은 "Saeed Rashid Al Qubaisi", 별칭은 "Saeed Rashed Al-Qubaisi"다. 음성 전사 관행이 제각각이라 데이터베이스 간 이름 대조에 혼란이 생긴다는 ICAO 자료가 있다 | [문헌○] ADGM, SAMA(S77), ICAO. [확인] Wikidata |
| 도구 | 번역하는 LLM은 모호한 곳을 표시하지 않고 하나로 정해 넘길 수 있다. 이 프로젝트는 이것을 "모호성 은폐"라 부른다. 의도적 조작이 아니라 specification gaming의 한 형태다. 읽는 사람은 아랍어를 모르니 그 선택이 있었다는 사실조차 알 수 없다. 사람 번역가도 대안 표기를 표시하지 않는 것은 마찬가지다 | [가설, 질문 Q1] |

**누구의 문제인가 (ADR-008, ADR-021. 2026-10-21 순위 교체):**

- 1순위: 걸프에 진출한 외국 중소기업·창업자. 상업등기, 정부 서신, 현지 상대방 계약을 내부 검토용으로 읽는다. 사내 아랍어 인력이 없고 여권 같은 신분증 근거가 없다. 근거는 문서 안 라틴 표기와 회사가 직접 확정한 표기(회사 사전)다.
- 2순위(보류): 걸프 법인 고객을 받는 은행·핀테크·결제사의 KYC·컴플라이언스 팀. 온보딩 서류 묶음의 아랍어 상업등기·정관에 적힌 회사명, 대표자·실소유자 이름이 여권 사본과 같아야 한다. 이름은 같거나 다르거나 둘 중 하나인 이진 기준이고, 근거(여권)가 같은 묶음 안에 있다 [가설].
- 대상이 아닌 사람: 아랍어를 읽는 사람이 있는 조직(문제가 없다), 번역사무소(대체 대상), 법원·관청 제출용 문서(면허 번역사가 해야 한다).

비용은 틀린 표기 자체보다 늦게 발견하는 데서 생긴다. 사우디의 영문 이름 수정은 무료이고 몇 분이면 끝나지만, 발견이 늦으면 계좌 개설 거부나 등록 지연으로 이어진다 [문헌○, S152~S159]. 손실 금액과 빈도를 보여 주는 공개 자료는 없다 [미확인].

**지금 있는 수단으로 안 되는 이유:**

| 수단 | 왜 부족한가 |
| --- | --- |
| 사람 번역가 | 장당 사우디 약 2.4만 원, UAE 약 6.0만 원. 내부 검토용에는 과하고, 대안 표기를 표시하지 않는다 |
| 범용 LLM 좌석 | 지시 없이는 이름의 45%를 말없이 찍고(EXP-003 C0 0.555), 다듬지 않은 지시로는 93%(C1p0), 원칙을 분명히 한 지시문 p1로는 99.9%다[확인, 합성 문서]. 곧 읽기 자체는 지시문으로 거의 해결된다. 좌석에 없는 것은 코드의 인용 검증, 회사 사전(확정한 표기의 재사용), 기록이다(ADR-021) |
| 이름 매칭·스크리닝 벤더 | 두 영문 이름이 같은 사람인지 점수를 낸다. 문서 속 아랍어 이름을 근거와 함께 영문 표기로 읽는 앞단은 하지 않는다 |

## 1.2 서비스 목표

핵심 약속은 "정확한 번역"이 아니라 **"확인해야 할 곳을 빠뜨리지 않고, 근거와 함께 알려 준다"**다. 보증의 세기는 "전수 검토를 건너뛰어도 된다"가 아니라 "어디를 확인해야 하는지 안다"다(ADR-008). 목표마다 6절의 지표를 붙여, 말이 아니라 측정으로 달성 여부를 판정한다.

| 번호 | 목표 | 지표 ([6절](evaluation.md)) | 판정 기준 |
| --- | --- | --- | --- |
| G1 | **드러낸다.** 독법·표기가 갈리는 구간을 빠뜨리지 않고 표시한다 | 몰래 정함 비율(말없이 찍음 + 근거 없는 확정), 말없이 찍음 비율(주 지표), 이름 미처리 수(일반 단어 미처리는 보조, ADR-014) | 몰래 정함 비율 0.10 이하 [확정, 2026-10-20] |
| G2 | **근거 없이 확정하지 않는다.** 고유명사는 문서(단계 2부터는 서류 묶음) 안에 근거가 있을 때만 확정하고 인용을 붙인다 | 근거 없는 확정 비율, 고확신 무근거 확정 토큰 수, 근거 검증 실패 수 | 근거 없는 확정 비율 0.02 이하 [확정, 2026-10-20]. 0이 목표이고, 코드가 보류로 고쳐 주지 않고 실패로 센다([4.5절](architecture.md)) |
| G3 | **전부 보류로 도망가지 않는다.** 근거가 있으면 확정하고, 모호하지 않은 곳에는 표시를 붙이지 않는다 | 과잉 표시 토큰 수, 보류율, 근거 채택 검증 통과율, 단계 2의 묶음 근거 확정률 | 근거 채택 검증 통과율 0.90 이상 [확정, 2026-10-20]. G1·G2를 과잉 보류로 맞추면 이 기준에서 떨어진다. 묶음 근거 확정률 목표는 합성 KYC 묶음에서 정한다 [제안] |
| G4 | **지시만 준 범용 LLM보다 낫다.** 그렇지 않으면 단독 제품이 아니라 공개 벤치마크·연구 산출물로 마무리한다 | C1 대 C2·C3의 합격선 지표 차이(같은 문서를 짝지은 부트스트랩 구간), 반복 간 일치율 | C1이 G1~G3 합격선을 넘으면 "지시만으로 충분"으로 보고 중단한다 [확정, 2026-10-20]. 판정 규칙은 [3절](scope.md) |
| G5 | **업무 흐름에 맞는 출력.** 결과는 근거 위치가 붙은 확인 대기 목록이고, KYC 담당자가 여권을 보고 항목을 닫을 수 있다. 판매 형태는 API다 | 항목당 근거 위치·인용 유무, 보류 후보 적중률(보류한 이름의 후보에 실제 표기가 드는가, ADR-014), 비용·지연(문서당) | 단계 2에서 정한다. 가격 천장은 번역료의 20% [가정] |
| G7 | **이름은 99% 이상 맞는다(서비스 요구, 2026-10-21 사용자 확정, ADR-017).** 어려운 경우(동명이인, 형식이 다른 근거, 함정 근거, 긴 문서)가 섞여도 이름 부분마다 말없이 틀리지 않고(안전), 기대 처분과 정확히 맞는다(엄격) | 안전·엄격 정확도(이름 부분 등장마다, [6.4절](evaluation.md)), 서비스 기준 하한(Clopper–Pearson·문서 단위 부트스트랩) | 두 정확도 모두 0.99 이상(점추정, EXP-003 판정). "99% 달성"이라는 문구는 한쪽 95% 하한도 0.99 이상일 때만. 합성 문서 기준이며 실제 서류로 일반화하지 않는다(G6) |
| G6 | **측정한 범위에서만 약속한다.** 합성 문서, Wikidata 실명, 공개 이중언어 문서로 잰 값만 말하고, 실제 고객 서류의 포착률로 일반화하지 않는다 | 실행마다 데이터 범위·모델·프롬프트 해시 기록([6.3절](evaluation.md)) | 기록이 없는 결과는 보고하지 않는다 |

**목표가 아닌 것 (단계 1~3 공통):**

- 번역 문장의 품질을 높이거나 평가하는 것
- 법원·관청 제출용 공인 번역을 대체하는 것
- 스캔본 문자 인식, 사람 검수, 한국어 출력
- 이름이 아닌 모호 구간의 최종 판단. 이것은 고객이 하고, 번역가에게 넘기는 연결은 추후 과제다

**G7과 EXP-002·003:** EXP-002의 합격선(G1~G3)은 쉬운 시험지(synthetic-v2)에서 C1~C3가 모두 만점이라 조건을 가르지 못했다(반복 1회, 보류). EXP-003은 어려운 시험지에서 G7의 99% 기준으로 G4(지시만 준 LLM보다 낫다)를 다시 쟀다. 2026-10-21 결과는 `stop`이다: 지시문 p1만 준 C1이 엄격 0.9993·안전 1.0으로 99%를 넘었고(합성 문서 기준, 반복 1회), 분석기 조건과의 차이는 없었다. 옛 지시문 p0로는 0.93이었다. G7은 이 합성 시험지에서 지시문만으로 충족됐고, G4의 근거(도구가 지시만 준 LLM보다 낫다)는 서지 않았다[확인, 사람 확인 남음].

**사업 판정과의 연결:** G4가 첫 관문이다. 범용 LLM이 지시만으로 이름 모호성을 잡으면 가격 천장이 LLM 좌석 값으로 내려가고 경제성이 사라진다(사업성 검토 3절). 그다음이 G2·G3의 묶음 근거 확정률(KYC 판매 문구를 정함)이고, 마지막이 단계 3의 멀티 에이전트 비교("독립된 두 번째 확인"을 판매 문구에 넣을지 정함, ADR-009)다.

## 1.3 단계 1에서 답할 질문

| ID | 질문 | 데이터 | 실험 |
| --- | --- | --- | --- |
| Q0 | 형태소 분석기가 실제 걸프 인명에서 독법 후보를 얼마나 내는가, 그 후보가 실제 영문 표기를 포함하는가 | 실제(Wikidata) | EXP-001 |
| Q1 | 에이전트가 정말 말없이 찍는가 | 합성 문서 | EXP-002 C0 |

| Q3 | 형태소 분석기를 주면 더 잡는가 | 합성 문서 | EXP-002 C2·C3 대 C1 |

어느 질문도 답을 가정하지 않는다. Q0의 결과가 Q3의 해석을 좌우한다. 분석기가 이름에서 후보를 거의 못 내면 C2·C3의 이득은 일반 단어에서만 나올 수 있다.


## 1.4 요구사항 (구 `docs/요구사항-분석.md`, 2026-10-13 작성, ADR-014 반영)

### 결론

단계 1의 시스템은 제품 시제품이 아니라 실험 장치다. 아랍어 → 영어 번역 에이전트가 독법이 갈리는 곳을 말없이 넘기는지(모호성 은폐) 재고, "모호하면 표시하라"는 지시와 형태소 분석기 도구가 그것을 줄이는지 비교한다. 그래서 기능 요구는 번역, 처분, 고유명사 대조표 셋으로 줄였고, 비기능 요구는 측정이 LLM에 기대지 않을 것, 재현할 수 있을 것, 기록이 남을 것에 두었다.

사용자는 아랍어를 못 읽는데 아랍어 문서에 책임을 지는 사람이다. 이 사람은 번역이 어느 독법을 골랐는지 스스로 알 수 없다. 제품이 약속하는 것은 "정확한 번역"이 아니라 "모호 구간을 얼마나 잡아내는가"다.

| FR2 | 모든 아랍어 토큰의 독법 후보를 형태소 분석기로 열거하고, 분석 수(0 포함)와 모호 여부를 남긴다 | `analyze` 노드 (`analyzer.py`) |

| FR5 | 고유명사마다 로마자 후보, 채택 표기, 근거를 내고, 근거가 없으면 보류한다 | `agent` 노드, `reconcile` 강등 규칙 |

| FR8 | 같은 아랍어 이름이 서로 다른 로마자로 채택되면 불일치로 센다 | `reconcile` 노드 |

| FR13 | 실제 걸프 인명(Wikidata)으로 분석기의 고유명사 후보를 잰다 | `data/wikidata.py`, `experiments/exp001.py` |

### 비기능 요구사항

| ID | 요구사항 | 충족 위치 |
| --- | --- | --- |
| NFR1 | 측정 독립성: 분석기는 조건과 무관하게 항상 돈다. 분석기를 쓸 수 없으면 LLM으로 대체하지 않고 멈춘다 | `analyze` 노드, `AnalyzerUnavailable` |
| NFR2 | 처분 확인과 지표 계산은 코드가 한다. LLM에게 자기 누락을 세게 하지 않는다 | `reconcile` (LLM 호출 없음, 단위 테스트) |
| NFR3 | 재현성: seed, 모델, 프롬프트 해시, 분석기·DB 버전, 일치 규칙 버전을 실행마다 남긴다 | `run_meta.json` |
| NFR4 | 관찰 가능성: LangSmith로 추적하고 지표를 메타데이터로 붙인다. 키가 없으면 추적만 꺼진다 | `config.configure_tracing`, `runner.Reviewer.run` |
| NFR5 | API 키 없이도 그래프 전체가 돈다(연습 모드) | `fake.py`, `--fake` |
| NFR6 | 정답 격리: 합성 문서의 정답 라벨은 프롬프트에 들어가지 않는다 | `runner.split_gold`, 테스트 `test_gold_never_reaches_the_model` |
| NFR7 | 형식 오류는 1회 재시도하고, 그래도 실패하면 실패한 채로 결과와 지표를 남긴다 | `validate` 노드와 조건 분기 |
| NFR8 | 비용 통제: 실제 LLM 실험은 명시적으로 동의해야 돈다 | `tashkeel exp002 --yes` |
| NFR9 | 라이선스: CAMeL 기본 DB(GPL v2)는 내부 측정에만 쓴다 | 계획 ADR-005 |
| NFR10 | 합성 데이터임을 표시하고 실존 인물을 넣지 않는다 | `data/synthetic.py`(Wikidata 레이블과 같은 전체 이름은 버림) |

### 범위 밖

스캔본과 문자 인식, 서류 묶음 검색의 실사용(틀만 있음), 이름 사전, 사람 검토 화면과 중단·재개, 멀티 에이전트, 인증·보안, 한글 표기, 번역 문장 품질 평가. 필요해 보여도 단계 1에는 넣지 않는다.

### 가정과 확인하지 않은 것

- 문맥이 있는 본문은 최신 LLM이 대부분 푼다고 본다. 측정하지 않았다 [가설].
- Wikidata 인명은 공개 인물 위주라 고객 서류의 이름 분포와 다를 수 있다 [가설].
- 합성 문서 템플릿의 아랍어 문장은 사람이 검수하지 않았다. 측정 대상이 이름이라 영향은 제한적이라고 본다 [가설].
- 합성 문서 결과는 실제 서류의 오류율이나 포착률이 아니다.
