# ADR-021 — 주 고객을 중소기업 내부 검토용으로 바꾸고, 제품을 "어떤 문서든 넣으면 이름 읽기 후보를 근거와 함께 제시하고 확정한 것만 회사 사전에 저장"으로 좁힌다

- 날짜: 2026-10-21
- 상태: 채택(구현 완료, 아래 "구현" 항목)
- 배경과 문제: EXP-003(어려운 합성 시험지, 99% 기준)에서 지시문 p1만 준 C1이 엄격 0.9993·안전 1.0으로 기준을 넘었고 분석기 조건(C2·C3)과 차이가 없었다([EXP-003](../experiments/EXP-003.md)). 사전 등록한 뜻대로 "분석기가 지시만 준 LLM보다 낫다"(G4)는 근거가 서지 않았다. 그런데 서비스 기본값은 측정한 설정과 달랐다(`config.py` `prompt_version="p0"`(93% 지시문), 화면·API 조건 기본 `C3`). 사용자는 결과를 보고 1순위 고객을 KYC 팀(ADR-009, 여권 근거·대상 ID 묶음)에서 **걸프에 진출한 외국 중소기업이 아랍어 서류를 내부 검토용으로 읽는 경우**로 바꾸기로 했다. 이 고객에게는 여권이 없고, 근거는 문서 안 라틴 표기와 **회사가 직접 확정한 표기**뿐이다.
- 사용자 결정(2026-10-21):
  1. 제품 한 줄: 어떤 문서를 넣어도 LLM이 실제 자료 근거를 바탕으로 고유명사 읽기 후보를 몇 가지 추천하고, 사람이 확정한 것만 회사별 DB에 올려 다음 문서에서 빠르게 찾아 확정한다.
  2. 보류 대상은 **고유명사만**(날짜·숫자·금액으로 넓히지 않는다).
  3. 입력 경로를 넓힌다. 스캔·PDF는 **무료 OCR API**를 쓰되 나중에 갈아끼울 수 있게 인터페이스만 두고, 인식 성능 실험은 하지 않는다.
  4. 화면은 두 페이지다. 파일 넣는 페이지(누르면 로컬 파일 선택)와 분석 결과 페이지(텍스트를 깔끔하게 뽑고 애매한 부분을 색으로 표시, 누르면 후보가 토글로 뜨고, 후보를 누르면 확정되어 DB에 적재).
  5. 그 밖의 기능은 구현하지 않는다. 장점으로 삼을 것은 보안(자체 배포 안에서 처리)과 회사별 사전이다. 추가 장점 후보 가운데 "자기 회사 표기 감시"만 로드맵에 [제안]으로 올린다.
- 검토한 대안:
  - (고객) KYC 팀 유지 / 중소기업 내부 검토용 / 둘 다. → 중소기업. 사업성 검토는 이 세그먼트를 "지불 의사가 가장 약하고 무료 LLM과 정면으로 겹침"으로 적었다. 차별점은 정확도가 아니라 기억(회사 사전)·검증(코드의 인용 검증)·기록·보안에 있다고 본다[가설].
  - (사전 키) 대상 ID 필수 유지 / 대상 ID 없이 고객 전체 / 거래처 단위. → 문서 단위 항목은 `entity_id="*"`(고객 전체)로 두고 묶음 경로는 "*"를 조회하지 않는다(ADR-018 "이름이 같다고 연결하지 않는다" 유지). 거래처 단위는 나중.
  - (사전 적용 위치) LLM 입력에 사전 표기를 넣음 / 코드가 결과 위에 덧씌움. → 덧씌움. p1 문구·해시를 보존하고 `ReviewResult`(골든·실험 경로)를 건드리지 않는다.
  - (OCR) OpenAI 비전 / Mistral / Google Document AI / 무료 API. → 사용자가 무료 API를 골랐다. 제3자 전송이라 "자체 배포 안에서 처리"와 어긋나는 점을 문서에 적고, 인터페이스를 교체 지점으로 둔다.
  - (인증 끈 서버의 사전 고객) 거부 / 기본 고객. → 기본 고객 `local`. 한 회사가 자체 배포하는 형태에 맞고 가짜 모델 체험에도 필요하다.
- 결정:
  - **기본값**: `PROMPT_VERSION` 기본 `p1`, 서비스 조건 기본 `C1`(`POST /v1/reviews`, `/v1/reviews/upload`, `/v1/bundles/{id}/reviews`). 실험 경로(`exp002`·`exp003`, 골든, 해시 핀)는 p0 기록을 그대로 둔다(`prompts.PROMPT_VERSION`, 골든 테스트의 명시 설정).
  - **회사 사전을 아무 문서에서**: `dictionary_apply.apply_dictionary`가 검수 결과의 고유명사마다 고객 + `"*"` + 정규화 아랍어로 조회해 덧씌움을 만든다. 보류·근거 검증 실패 + 적중 → `dictionary_adopt`; 문서 근거 확정 + 적중인데 표기가 다름 → `conflict`(확정하지 않음); 같음 → `agree`. 같은 이름의 여러 등장을 한 항목에 묶은 출력(`token_ids` [11, 86] → "نوال نوال")은 `name_text`가 반복을 걷어 키를 만든다. 등록은 사람이 후보를 누를 때만(`POST /v1/dictionary`에 `job_id + token_ids` 형태 추가), 목록 `GET /v1/dictionary`, 취소 `DELETE /v1/dictionary/{id}`. DB가 있으면 `name_items.evidence_source="glossary"`로 남긴다.
  - **입력 경로**: `ocr/` 패키지(`OcrBackend` 프로토콜, `ocrspace`·`none`), `extract_text`(.txt/.md 그대로, .pdf는 `pypdf` 텍스트 층 먼저, 아랍어가 없으면 OCR, 이미지는 OCR), `POST /v1/reviews/upload`(추출 → 구간 → 검수 한 번에), `POST /v1/extract`(추출만). 설정 `OCR_BACKEND`·`OCR_API_KEY`·`OCR_ENDPOINT`·`OCR_MAX_BYTES`·`UPLOAD_MAX_BYTES`.
  - **화면**: 해시 라우트 `#/upload`·`#/result/{job_id}`. 결과 응답에 `tokens`(토큰 위치)와 `dictionary`(덧씌움)를 더해 화면이 토큰 위치로 이름을 감싼다(문자열 치환이 아니라서 같은 이름이 여러 번 나와도 정확). 묶음 화면은 `#/bundle`로만 남긴다.
  - **보류**: KYC 묶음(대상 ID·MRZ·합성 KYC 묶음)과 멀티 에이전트 M1은 코드를 두되 추가 개발하지 않는다.
- 선택 이유와 근거: 측정한 설정(p1·C1)을 제품이 실행해야 측정값이 의미가 있다. 분석기를 빼면 문서당 원가가 약 절반이고(EXP-003 토큰 기준 C1 약 $0.05, C3 약 $0.10[계산]) GPL v2 형태소 DB(ADR-005)가 제품 경로에서 필수가 아니게 된다. 중소기업 담당자의 일은 "읽기"가 아니라 "건을 닫는 것"이고, 읽기 단계는 지시문으로 거의 공짜가 됐으므로 남는 가치는 근거 찾기·검증·기록·재사용에 있다. 실제 모델로 dev_005를 두 번 돌려 첫 번에 보류된 이름을 확정하자 두 번째 결과가 처음부터 사전 확정으로 나왔다[확인, 2026-10-21, `docs/과제2-테스트-기록.md` 7절].
- 비용·성능·구조에 미치는 영향: 단일 문서 경로·실험·골든·해시는 바뀌지 않는다(골든·해시 테스트가 p0를 명시). 사전은 Alembic 변경 없이 기존 표를 쓴다(`entity_id="*"`). 결과 응답이 `tokens`·`dictionary`·`dictionary_customer`만큼 커진다. 무료 OCR은 파일을 제3자에게 보낸다. 분석기는 여전히 돈다(측정 지표용, NFR1). 테스트 512개 통과.
- 재검토 조건: 같은 고객 안에서 같은 아랍어 철자가 다른 사람일 때 사전이 잘못 확정하는 일이 실제 서류에서 나타날 때(거래처 단위 키). 인증을 켠 다중 고객 배포에서 `local` 고객이 문제가 될 때. 로컬 OCR이 필요해질 때. 사용자가 날짜·숫자 보류를 요구할 때.
- 관련 코드·실험·트러블슈팅: `src/tashkeel_check/dictionary_apply.py`, `ocr/`, `bundle/dictionary.py`, `web/app.py`, `web/jobs.py`, `web/db.py`, `web/static/index.html`, `tests/test_dictionary_apply.py`, `tests/test_ocr_extract.py`, `tests/test_web_upload_dictionary.py`, [EXP-003](../experiments/EXP-003.md).
- 대체하거나 대체된 ADR: ADR-009(1순위 고객·판매 형태)를 대체한다. ADR-008(걸프 영어권 최종 사용자, 사람 검수 없음)과 ADR-010(사전은 사람이 닫을 때만 등록)·ADR-018(묶음 경로의 대상 ID 규칙)은 그대로다. ADR-005의 "배포 형태 전 법률 검토"는 분석기가 제품 경로의 필수 부품이 아니게 되어 범위가 줄었다.
