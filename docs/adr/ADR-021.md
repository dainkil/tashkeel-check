# ADR-021 — 주 고객을 중소기업 내부 검토용으로 바꾸고, 제품을 "어떤 문서든 넣으면 이름 읽기 후보를 근거와 함께 제시하고 확정한 것만 회사 사전에 저장"으로 좁힌다

- 날짜: 2026-10-21
- 상태: 채택(구현). ADR-009를 대체. 서비스 기본 C1과 M1 보류는 ADR-022가 뒤집음
- 배경: EXP-003에서 지시문 p1만 준 C1이 엄격 0.9993·안전 1.0으로 기준을 넘었고, 분석기 조건(C2·C3)과 차이가 없었다([EXP-003](../experiments/EXP-003.md)). "분석기가 지시만 준 LLM보다 낫다"(G4)는 근거가 서지 않았다. 서비스 기본값(p0, 조건 C3)도 측정한 설정과 달랐다. 사용자는 1순위 고객을 KYC 팀에서 걸프에 진출한 외국 중소기업의 내부 검토용으로 바꾸기로 했다. 이 고객에게는 여권이 없고, 근거는 문서 안 라틴 표기와 회사가 직접 확정한 표기뿐이다.
- 결정: 제품을 "어떤 문서든 넣으면 고유명사 읽기 후보를 근거와 함께 제시하고, 사람이 확정한 것만 회사 사전에 저장해 다음 문서에서 바로 확정"으로 좁힌다. 기본값을 측정한 설정(p1·C1)으로 바꾸고, 사전 덧씌움·파일 업로드와 OCR 인터페이스·두 페이지 화면을 만든다.
- 결정 이유: 측정한 설정을 제품이 실행해야 측정값이 의미가 있다. 분석기를 빼면 문서당 원가가 약 절반이고(C1 약 $0.05, C3 약 $0.10[계산]), GPL v2 형태소 DB(ADR-005)가 제품 경로에서 필수가 아니게 된다. 읽기는 지시문으로 거의 해결됐으므로 남는 가치는 근거 찾기·검증·기록·재사용이다[가설].
- 고려한 대안: (고객) KYC 팀 유지 / 둘 다. (사전 키) 대상 ID 필수 유지 / 거래처 단위(나중에). (사전 적용) LLM 입력에 사전 표기를 넣음(p1 해시와 `ReviewResult`가 바뀜). (OCR) OpenAI 비전 / Mistral / Google Document AI(사용자가 무료 API를 고름). (인증 끈 서버의 사전) 거부.
- 최종 결정:
  - 기본값은 `PROMPT_VERSION=p1`, 서비스 조건 C1이다. 실험 경로는 p0 기록을 그대로 둔다.
  - 회사 사전: `dictionary_apply`가 고객 + `"*"` + 정규화 아랍어로 조회해 결과 위에 덧씌운다. 보류 + 적중이면 사전 확정, 문서 근거와 다르면 충돌, 같으면 동의다. 등록은 사람이 후보를 누를 때만 하고(`POST /v1/dictionary`), 목록·취소 API를 둔다. 묶음 경로는 `"*"`를 조회하지 않는다(ADR-018 유지). 인증을 끈 서버는 고객 `local`을 쓴다.
  - 입력: `ocr/`(`OcrBackend`: `none`·`ocrspace`)와 `extract_text`(txt·md는 그대로, PDF는 텍스트 층 먼저), `POST /v1/reviews/upload`, `POST /v1/extract`. 무료 OCR은 파일을 제3자에게 보낸다는 점을 문서에 적는다. 인식 성능은 재지 않는다.
  - 화면: `#/upload`·`#/result/{job_id}`. 결과 응답에 `tokens`·`dictionary`를 더해 토큰 위치로 이름을 표시한다.
  - 보류 대상은 고유명사만이다. KYC 묶음과 M1은 코드만 두고 추가 개발하지 않는다.
  - 확인: 실제 모델로 dev_005를 두 번 돌려, 첫 번에 확정한 이름이 두 번째에 처음부터 사전 확정으로 나왔다(`docs/과제2-테스트-기록.md` 7절). 테스트 512개 통과.
  - 재검토: 같은 철자의 다른 사람을 사전이 잘못 확정할 때(거래처 단위 키), 로컬 OCR이 필요할 때, 날짜·숫자 보류 요구가 생길 때.
