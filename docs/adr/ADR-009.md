# ADR-009 — 1순위 고객을 KYC·컴플라이언스 팀으로, 판매 형태를 멀티 에이전트 API로 둔다

- 날짜: 2026-10-20
- 상태: ADR-021로 대체(2026-10-21)
- 배경: ADR-008로 고객을 걸프 영어권 최종 사용자로 넓혔지만 세그먼트 우선순위와 판매 형태가 없었다. 사용자가 "어떻게 누구에게 파는 게 유리한가"를 물었고, 단일 에이전트를 중간 단계로 봤다.
- 결정: 1순위 고객을 걸프 법인 고객을 받는 은행·핀테크·결제사의 KYC·컴플라이언스 팀으로 두고, 멀티 에이전트 API로 판다.
- 결정 이유: KYC에서 이름은 신분증과 같아야 하는 이진 기준이다(SAMA 회람 S77, UAE 중앙은행 주제 검토 S82). 여권 사본이 온보딩 묶음에 들어 있어 묶음 근거 검색이 그대로 업무 흐름이 된다[가설]. 이미 돈이 흐르는 문제이고(LSEG S80, Dow Jones S81, Rosette S147), 기존 벤더는 매칭 점수를 낼 뿐 문서 속 이름을 근거와 함께 읽는 앞단은 비어 있다. 고객당 문서량이 커서 손익분기가 10.5곳(급여)이다(셀프서브는 105곳).
- 고려한 대안: 걸프 진출 외국 중소기업 셀프서브 우선 / 국제 로펌 실사팀 / 외국계 법인 HR / 번역 플랫폼·법률 AI에 부품 공급.
- 최종 결정:
  - 묶음 단위 종량에 월 최소 금액을 붙인다. 2순위는 체험·유입용 중소기업 셀프서브 웹이고, 로펌·HR은 보류한다. RegTech·KYC 플랫폼은 유통 경로로 본다.
  - 판매 형태(번역 에이전트, 격리된 검증 에이전트, 중재자)는 단계 3에서 단일 에이전트보다 나을 때만 쓴다.
  - 영향: 단계 2에서 API와 묶음 근거 검색이 핵심이 되고, 합성 KYC 묶음 생성기가 필요하다. 은행·핀테크 판매에는 SOC 2(첫해 약 4,100만 원, 6~12개월)가 사실상 먼저 필요하다[가설].
  - 재검토: 합성 KYC 묶음에서 근거 확정률이 낮을 때, 멀티 에이전트가 낫지 않을 때, 은행 정책이 공인 번역만 인정할 때.
  - 이후: EXP-003 결과를 보고 ADR-021이 1순위 고객을 중소기업 내부 검토용으로 바꿨다.
