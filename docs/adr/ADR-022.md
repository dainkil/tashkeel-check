# ADR-022 — 서비스 기본 경로를 조건 M2(두 agent + 회사 기록 툴 MCP + 회사 문서 보관함)로 바꾸고, 측정 없이 완제품부터 만든다

- 날짜: 2026-10-22
- 상태: 채택(구현 완료, 정확도 미측정). ADR-021의 기본 C1·M1 보류를 뒤집음
- 배경: ADR-021 뒤의 기본 경로(C1)는 LLM을 한 번 부르고 끝나며 도구가 없어 agent라 부르기 어렵다. 사용자는 agent·RAG·MCP·멀티 에이전트가 모두 실제 제품 경로에 들어가기를 원했다. 과제 2가 요구하는 것은 아니므로 각 부품은 기능적인 일을 맡아야 한다. EXP-003에서 C1이 문서 안의 읽기를 거의 다 풀었으므로 새 구조가 기여할 곳은 문서 밖 근거다. 예를 들어 지난달 임대차 계약서에는 영문 표기가 있었는데 이번 정부 통지에는 아랍어만 있는 경우다.
- 결정: 서비스 기본 경로를 조건 M2(번역 agent와 검증 agent + 회사 기록 툴 MCP + 회사 문서 보관함 RAG + 코드 중재자)로 바꾸고, 실험 없이 완제품부터 만든다. 보관함은 제안만 하고 확정은 사람이 한다.
- 결정 이유: 네 부품이 모두 "문서 밖 근거를 찾아 사람에게 보여 주기"라는 한 가지 일을 맡는다. agent는 무엇을 찾을지 고르고, RAG는 지난 서류에서 찾고, MCP는 그 기록을 고객 범위로 묶어 내주고, 멀티 에이전트는 서로 모르는 두 판단을 겹친다. 보관함 선택은 확정을 바꾸지 못하고 화면에 내기 전에 원문으로 다시 확인하므로, "근거 없이 확정하지 않는다"(G2)와 ADR-018이 코드로 계속 보장된다. 고객 범위를 서버 쪽 토큰으로 정하므로 보관함 글에 지시문이 숨어 있어도 최악의 결과는 엉뚱한 제안이다. 기본 경로를 바로 바꾸는 것, 실험을 빼는 것, `/mcp` 외부 공개를 미루는 것은 사용자 결정이다(2026-10-22).
- 고려한 대안:
  - (위치) 새 모드로 추가하고 측정 뒤 승격. 사용자가 바로 바꾸기로 했고, 되돌리기 설정 `REVIEW_CONDITION=C1`을 둔다.
  - (RAG 자료) 공개 표기 사례(Wikidata 걸프 인명). 근거가 아니라 후보만 늘리고 회사·기관 이름을 다루지 못한다.
  - (역할) 근거 탐색 agent를 따로 둔 3역할. LLM 호출이 3회다.
  - (측정) 합성 보관함 데이터 + dev 실측 / eval까지. 사용자가 실험을 빼기로 해 가짜 모델 테스트와 실제 모델 작동 확인만 한다.
  - (MCP 전송) stdio 하위 프로세스가 Postgres를 직접 읽음. 메모리 저장소를 볼 수 없고, 고객을 도구 인자로 받아야 해 외부 호출자를 격리할 수 없다.
  - (벡터 저장) pgvector / 메모리 Qdrant. 이름 일치가 먼저이고 임베딩은 몇 개 후보의 순서만 정하므로 실수 배열 + Python 코사인으로 충분하다. 확장 설치가 필요 없고 ADR-011을 지킨다.
- 최종 결정:
  - M2: `ENGINE_CONDITIONS=("M1","M2")`이고 C0~C3·골든·해시·실험 계획은 그대로다. 번역 agent(C1 입력 + `C1_SYSTEM_P1` + 기록 툴 규칙, 출력 `AgentOutputM2`)와 검증 agent(같은 입력, 번역 agent 출력은 보지 않음, 출력 `VerifierOutputM2`)가 동시에 돌고, 기록 툴은 역할당 최대 2번 부른다. 중재자는 M1의 `arbitrate()`를 그대로 쓴다(문서 안 근거, 같은 철자, 근거 검사 통과일 때만 확정). 보관함 선택은 보류된 이름에 대해, 그 역할의 툴이 실제로 돌려준 `hit_id`만 `metrics.engine.archive`에 적는다.
  - 회사 기록 MCP 서버(`mcp/records.py`, 툴 `search_company_records`): 사람이 확정한 사전 표기가 있으면 그것을, 없으면 보관함 구절을 돌려준다. 같은 프로세스에서 `FastMCPTransport`로 붙는다. 고객 범위는 작업마다 발급하고 끝나면 없애는 128비트 토큰을 MCP `_meta`로만 받는다. 쓰기·확정 도구는 없고, LLM은 토큰 ID 묶음만 넘긴다.
  - 문서 보관함(`archive/`): 검수를 마친 업로드·붙여넣기 서류만 넣고(조건과 무관), 아랍어가 있고 그 구간이나 다음 구간에 라틴 문자가 있는 구간만 구절로 남긴다. 찾기는 이름 단어 일치(접두 و·ب·ل·ف·ك 허용, 공백 뺀 3글자 미만 제외) → 문맥 임베딩 유사도 순 → 이름당 4개다. 저장은 메모리 또는 Postgres(Alembic 0004). 임베딩은 실제 모델 서비스면 OpenAI(`EMBEDDING_MODEL`, 보관함 글이 OpenAI로 감), 가짜 모델이면 연습용 n-gram이다.
  - 보관함 덧씌움(`archive_apply.py`): 사전 덧씌움 다음에 돌고 사전이 이긴다. 원문을 다시 읽어 같은 고객인지, 이번 서류가 아닌지, 이름이 구절에 있는지, 철자가 글자 그대로 있는지 확인한 뒤 `archive_suggest` 또는 `archive_conflict`를 낸다. 사람이 제안을 누르면 `archive_hit_id`로 사전에 등록되고, 근거 서류는 그 지난 서류로 남는다.
  - 서비스: `REVIEW_CONDITION`(기본 M2). 묶음 경로는 M2를 받지 않는다. `/v1/archive`(목록·삭제)와 `/health` 항목을 더하고, 근거 검사는 따로 주지 않으면 v2를 쓴다. 화면은 처음에 보관함 제안을 보라색으로 표시했다가, 같은 날 이름 색을 셋(확정·확인 필요·사전과 문서가 다름)으로 줄였다.
  - 영향: 문서당 약 $0.10~0.12, 80~100초로 C1의 약 2배다[추정, 미측정]. 기본값의 정확도는 재지 않았고, README의 99%는 C1 값이다. 두 agent가 일치해야 확정하므로 C1보다 보류가 늘 수 있다[가설]. 범위 토큰이 LangSmith 그래프 입력에 남을 수 있지만, 같은 프로세스에서만 쓰이고 작업이 끝나면 없어지므로 받아들인다. 테스트 559개 통과.
  - 재검토: M2를 측정(EXP-005 [제안])했을 때 C1보다 낮거나 코드만 쓰는 보관함 조회(A0)보다 낫지 않으면 C1 + A0로 되돌린다. 같은 철자의 다른 대상 제안이 자주 나오면 거래처 단위 범위를 둔다. 외부 MCP 클라이언트가 필요하면 `/mcp`를 API 키 인증으로 연다. 보관함이 커지면 pgvector로 옮긴다.
  - 연결: ADR-019(M1)를 기본 경로로 넓히고 ADR-012(MCP 범위)를 넓힌다. ADR-010·011·018은 지킨다.
