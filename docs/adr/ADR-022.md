# ADR-022 — 서비스 기본 경로를 조건 M2(두 agent + 회사 기록 툴 MCP + 회사 문서 보관함)로 바꾸고, 측정 없이 완제품부터 만든다

- 날짜: 2026-10-22
- 상태: 채택(구현 완료, 정확도 미측정)
- 배경과 문제:
  - ADR-021 뒤의 기본 경로(C1)는 LLM을 한 번 부르고 끝난다. 도구가 없고, 판단은 코드가 한다. 그래서 "agent"라고 부르기 어렵다.
  - 사용자는 agent·RAG·MCP·멀티 에이전트가 모두 실제 제품 경로에 들어가기를 원했다. 과제 2는 이 넷을 요구하지 않는다(ADR-012). 따라서 각 부품은 장식이 아니라 기능적인 일을 맡아야 한다.
  - EXP-003에서 C1이 문서 하나 안의 읽기를 이미 거의 다 풀었다(합성 eval 엄격 0.9993·안전 1.0). 그래서 새 구조가 기여할 곳은 **문서 밖 근거**다. 예를 들어 지난달 임대차 계약서에는 영문 표기가 있었는데 이번 정부 통지에는 아랍어만 있는 경우다. 지금 제품은 이런 이름을 보류로만 둔다.
- 사용자 결정(2026-10-22):
  1. 기본 경로를 바꾼다(새 모드 추가가 아니라).
  2. RAG 자료는 회사 문서 보관함(이 고객이 전에 올린 서류)으로 한다.
  3. 멀티 에이전트는 기존 M1에 도구를 더한다(역할을 새로 나누지 않는다).
  4. **실험은 빼고 완제품부터 만든다.**
  5. 외부 MCP 클라이언트용 `/mcp` 공개는 뒤로 미룬다.
- 검토한 대안:
  - (위치) 새 모드로 추가하고 측정 뒤 기본값으로 승격 / 기본 경로를 바로 바꿈. → 사용자가 바로 바꾸기로 했다. 되돌리기 설정(`REVIEW_CONDITION=C1`)을 둔다.
  - (RAG 자료) 회사 문서 보관함 / 공개 표기 사례(Wikidata 걸프 인명 풀) / 둘 다. → 보관함. 공개 사례는 근거가 아니라 후보만 늘리고, 회사·기관 이름은 다루지 못한다.
  - (역할) M1에 도구 추가 / 근거 탐색 agent를 따로 둔 3역할. → M1에 도구 추가. 3역할은 LLM 호출이 3회다.
  - (측정) 합성 보관함 데이터 + dev 실측 / 가짜 모델 테스트만 / eval까지. → 처음에는 dev 실측을 골랐다. 이후 "실험은 빼고 빨리 완제품부터"로 바꿔, 가짜 모델 테스트와 실제 모델 작동 확인만 한다.
  - (MCP 전송) 회사 기록 서버를 FastAPI 안에 두고 메모리 전송으로 붙임 / stdio 하위 프로세스가 Postgres를 직접 읽음. → 메모리 전송. stdio 프로세스는 메모리 저장소를 볼 수 없어 DB 없는 실행에 두 번째 경로가 필요하다. 또 고객을 도구 인자로 받아야 해서 외부 호출자를 격리할 수 없다.
  - (벡터 저장) pgvector / 메모리 Qdrant / 실수 배열 + Python 코사인. → 실수 배열. 검색은 (고객, 정규화 아랍어 이름) 일치가 먼저이고, 임베딩은 몇 개 안 되는 후보의 순서만 정한다. 로컬 테스트 DB에 `CREATE EXTENSION`이 없어도 되고, 임베딩 차원(OpenAI 1536, 연습용 512)이 섞여도 된다. ADR-011(Postgres만)을 지킨다.
- 결정:
  - **조건 M2**: `ENGINE_CONDITIONS=("M1","M2")`. `CONDITIONS`(C0~C3)·골든·해시·실험 계획은 그대로 둔다.
    - 번역 agent: C1 입력(분석기 블록 없음) + `C1_SYSTEM_P1` + 규칙 8(기록 툴). 출력은 `AgentOutputM2`(항목마다 `archive{hit_id, spelling}`).
    - 검증 agent: 같은 입력. 번역 agent 출력은 보지 않는다. 출력은 `VerifierOutputM2`.
    - 두 역할은 동시에 돈다. 회사 기록 툴은 역할당 최대 2회 부른다.
    - 코드 중재자는 `archive`를 떼고 M1 `arbitrate()`를 그대로 부른다. 확정 규칙은 M1과 같다(둘 다 문서 안 근거, 같은 철자, 근거 검사 통과).
    - 보관함 선택은 보류로 남은 이름에만, 그 역할의 툴이 실제로 돌려준 `hit_id`만 `metrics.engine.archive`에 적는다.
    - M2 지시문은 p1에서만 정의한다.
  - **회사 기록 MCP 서버**(`mcp/records.py`): 툴 `search_company_records`. 사람이 확정한 사전 표기가 있으면 그것을, 없으면 보관함 구절을 돌려준다.
    - 서버는 Runtime의 사전·보관함을 그대로 쓰고, `FastMCPTransport`로 같은 프로세스에서 붙는다.
    - 고객 범위는 작업마다 발급하고 끝나면 폐기하는 128비트 토큰을 MCP `_meta`로만 받는다. 도구 인자로는 받지 않는다.
    - 쓰기·확정 도구는 없다.
    - LLM은 토큰 ID 묶음만 넘기고, 아랍어·문맥은 래퍼가 만든다.
  - **회사 문서 보관함**(`archive/`): 검수를 마친 업로드·붙여넣기 서류만 넣는다(조건과 무관).
    - 아랍어가 있고 그 구간이나 다음 구간에 라틴 문자가 있는 구간을 구절로 남긴다.
    - 찾기: 이름 단어열이 구절에 단어 단위로 있는가(접두 و·ب·ل·ف·ك 허용, 공백 뺀 3글자 미만은 찾지 않음) → 이번 서류 문맥과의 임베딩 유사도 순 → 이름당 4개.
    - 저장소는 메모리 또는 Postgres(Alembic 0004 `archive_documents`·`archive_passages`). 0004는 `documents.customer_id`를 채우고 되채운다.
    - 임베딩은 실제 모델 서비스면 OpenAI(`EMBEDDING_MODEL`), 가짜 모델이면 연습용 n-gram이다.
  - **보관함 덧씌움**(`archive_apply.py`): 사전 덧씌움 다음에 돌고, 사전이 이긴다.
    - 보관함 원문으로 다시 확인한다: 같은 고객인가, 이번 서류(ID·파일 해시)가 아닌가, 이름이 구절에 있는가, 철자가 글자 그대로 있는가(`strict_words_in_quote`).
    - 결과는 `archive_suggest`(`agreement: both | one`) 또는 `archive_conflict`다. 확정은 하지 않는다.
    - 사람이 제안을 누르면(`POST /v1/dictionary`의 `archive_hit_id`) 사전에 등록된다. 근거 서류는 그 지난 서류다.
  - **서비스**:
    - `REVIEW_CONDITION`(기본 `M2`, `C1`로 되돌림). `ReviewRequest.condition`과 업로드 `condition`을 비우면 이 값을 쓴다.
    - `MULTI_AGENT`는 M1만 계속 막는다. 묶음 경로는 M2를 거부한다(묶음은 대상 ID로만 잇는다, ADR-018).
    - `/v1/archive`(목록·삭제), `/health`의 `default_condition`·`archive`·`records_mcp`.
    - 서비스는 `EVIDENCE_RULE`을 따로 주지 않으면 근거 검사 v2를 쓴다. EXP-003이 v2로 쟀는데 서비스 기본은 v1이었다. `Settings` 기본값은 골든에 묶여 있어 그대로 둔다.
  - **화면**: 보관함 제안 색(보라)과 범례, 후보 순서(사전 → 보관함 → 문서 근거 → LLM), 출처 서류·날짜·구절·일치 정도, 보관함 목록·삭제. 서류 검수 조건은 서버 기본을 따른다("가짜 모델이면 C3" 처리를 지움).
    - 후속(2026-10-22, 같은 날 사용자 결정): 이름 색을 셋(확정·확인 필요·사전과 문서가 다름)으로 줄여 보라는 없어졌다. 보관함 제안은 "확인 필요" 이름의 첫 후보와 출처 구절로 보인다. 화면 상단의 상태 줄(모델·조건·DB)도 지웠다([changelog](../changelog.md)).
  - **가짜 모델**: 연습 모드 M2는 번역하지 않는다. 아랍어 토큰을 하나씩 기록 툴로 찾고, 사전 표기나 첫 자음이 맞는 보관함 후보가 있는 것만 보류 항목으로 낸다.
- 선택 이유와 근거:
  - 네 부품이 모두 한 가지 일, 즉 "문서 밖 근거를 찾아 사람에게 보여 주기"를 맡는다. agent는 무엇을 찾을지 고르고, RAG는 지난 서류에서 찾고, MCP는 그 기록을 고객 범위로 묶어 내주고, 멀티 에이전트는 서로 모르는 두 판단을 겹친다.
  - "근거 없이 확정하지 않는다"(G2)와 "이름이 같다고 같은 대상으로 잇지 않는다"(ADR-018)는 코드로 계속 보장된다. 보관함 선택은 확정을 바꾸지 못하고, 화면에 내기 전 원문으로 다시 확인한다.
  - 고객 분리는 도구 인자가 아니라 서버 쪽 범위 토큰으로 한다. 보관함 글에 지시문이 숨어 있어도 최악의 결과는 엉뚱한 제안이다.
- 비용·성능·구조에 미치는 영향:
  - 문서당 LLM 호출이 2회 이상(두 역할 + 툴 왕복)이다. 약 $0.10~0.12로 C1($0.053)의 약 2배, 두 역할을 동시에 돌려 80~100초다 [추정, 미측정].
  - **기본값의 정확도는 재지 않았다.** README의 99%는 C1 값이다. 두 agent가 일치해야 확정하므로 단일 문서에서 C1보다 보류가 늘 수 있다 [가설].
  - C0~C3·M1의 지시문·스키마·해시, 골든 160건, 실험 경로는 바뀌지 않는다.
  - Alembic 0004가 표 2개를 더한다. 결과 응답에 `archive`가 더해진다.
  - 그래프 상태에 남는 범위 토큰이 LangSmith 그래프 입력에 남을 수 있다. 다만 같은 프로세스 메모리에서만 쓰이고, 외부 엔드포인트가 없고, 작업이 끝나면 폐기되므로 받아들인다. `Reviewer.run`의 추적 입력에서는 뺐다.
  - 테스트 559개 통과(Postgres 포함, 새 47개).
- 재검토 조건:
  - M2를 측정했는데(EXP-005 [제안]) 단일 문서 정확도가 C1보다 떨어지거나, 잘못된 제안 비율에서 코드만 쓰는 보관함 조회(A0)보다 낫지 않을 때. 그러면 C1 + A0로 되돌린다.
  - 실제 서류에서 같은 철자의 다른 대상 제안이 자주 나올 때. 그러면 거래처 단위 범위나 문맥 하한을 둔다.
  - 외부 MCP 클라이언트가 필요할 때. 그러면 `/mcp`를 API 키 인증으로 연다.
  - 보관함이 커져 Python 코사인이 느릴 때. 그러면 pgvector로 옮긴다.
