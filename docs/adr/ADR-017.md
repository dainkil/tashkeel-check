# ADR-017 — 어려운 시험지(synthetic-hard)와 99% 정확도 기준으로 EXP-003을 준비하고, 지시문 p1·근거 검사 v2·채점 v2를 더한다

- 날짜: 2026-10-21
- 상태: 채택(코드·dev 생성까지). 확인 지점 A 통과(2026-10-21, 사용자가 정답 규칙을 그대로 고정). eval 생성과 실행은 사용자 확인 뒤
- 배경과 문제:
  - EXP-002 반복 1회(120회)에서 C1·C2·C3가 모두 만점이었다(몰래 정함 0/174, 근거 채택 151/151, `docs/experiments/EXP-002.md`).
  - 원인은 시험지가 쉬운 데 있다고 본다[가설]. synthetic-v2에서는 근거가 늘 같은 사람의 영문 줄로 바로 옆에 그대로 있다. 생성기의 `exclude` 때문에 사람끼리 이름이 겹치지 않고, 함정도 없다. 그래서 C1의 규칙 4("문서 안에 그 이름의 로마자 표기가 있을 때만 확정")가 사실상 채점 기준이 됐다. 이 시험지로는 도구의 가치를 잴 수 없다(천장 효과).
  - 사용자 결정(2026-10-21):
    - EXP-002의 남은 240회는 보류한다.
    - 아주 어려운 경우까지 넣은 새 시험지와 답안지를 만든다.
    - 서비스 특성상 정확도는 99% 이상이어야 한다.
- 검토한 대안:
  - (99%의 단위) 이름 등장마다 / 문서마다 / 인물마다
  - (맞음 기준) 안전만 / 엄격만 / 둘 다
  - (판정) 점추정만 / 95% 하한만 / 두 단계
  - (지시문) p0 그대로 / 원칙만 분명히 / 함정 유형까지 나열
  - (규모) 전체 1,000개 이상 / 유형마다 500개 이상 / dev만 먼저
- 결정(사용자 확정 2026-10-21, 세부는 이 ADR에서 정함):
  - **99%의 단위:** 이름 부분(given·father·grandfather·family 등)이 나올 때마다 센다. عبد الله·آل X·أبو X처럼 토큰 둘인 부분은 하나로 세고, 아랍어 토큰 수도 같이 보고한다.
  - **두 기준을 모두 넘어야 한다.**
    - 안전 정확도: 말없이 틀린 이름이 나가지 않은 비율 ≥ 0.99.
    - 엄격 정확도: 기대 처분과 정확히 일치한 비율 ≥ 0.99.
    - 오류 종류와 어느 기준에 드는지는 `docs/evaluation.md` 6.4절에 있다.
  - **판정은 두 단계다.**
    - 조건 비교 판정은 점추정 ≥ 0.99로 한다.
    - "서비스 기준 99% 달성"이라는 문구(`service_claim`)는 반복마다의 한쪽 95% Clopper–Pearson 하한 중 가장 낮은 값과, 문서 단위 부트스트랩 한쪽 95% 하한이 모두 0.99 이상일 때만 쓴다.
  - **판정 구조는 EXP-002와 같다.**
    - stop: C1이 두 기준을 모두 넘음.
    - pass: C1은 못 넘고, C2나 C3가 넘으며 C1이 못 넘은 기준을 우연 이상으로 고침.
    - fail: 그 밖.
    - 판정별 의미는 실행 전에 `docs/experiments/EXP-003.md`에 적는다.
  - **엄격 철자:**
    - 대소문자, 공백, 하이픈, 아포스트로피, MRZ의 `<`, 연결어(bin·bint·ibn)만 무시한다.
    - 모음·겹자음·자음은 글자 그대로 같아야 한다.
    - 일치 규칙 v1(Hamed≈Hamad 허용, ADR-015)은 EXP-002 지표에만 쓴다. 신분증 표기와 같아야 한다는 R2에 맞추려는 것이다.
  - **정답 규칙(하나로 모든 기대 처분을 정한다):** 사람마다 이름 부분별로, 그 사람의 로마자 표기에 나온 완전한 철자(엄격 키)를 모은다. 이니셜과 생략은 세지 않는다.
    - 철자가 하나: 확정. 기대 표기는 그 철자다.
    - 철자가 둘 이상: 보류. 그 철자들을 모두 후보에 넣어야 한다.
    - 철자가 없음: 보류.
    - 다른 사람의 표기, 회사명·이메일·URL 속 이름은 근거가 아니다. 같은 사람이 다시 나오면 같은 처분을 따른다.
    - 판단이 갈릴 수 있는 정답은 `arguable`로 표시하고, 뺀 민감도 지표를 같이 낸다(판정에는 쓰지 않는다). 대상은 아버지에게만 근거가 있는 아들의 가문명·아버지 이름, 충돌 표기가 있는 사람의 나머지 부분, 라벨 없는 먼 곳 표기, 짧은 재등장이다.
  - **어려운 유형 17가지(A1~D5):** `docs/data.md` 5.3절에 정의가 있다. 유형은 실제 KYC 서류에서 생길 법한 것으로 먼저 정했다. 문서는 seed로 생성하고 모델 결과로 고르거나 버리지 않는다(ADR-014).
  - **규모:** eval 70개 문서, 이름 부분 약 1,400~1,600개. 이 값은 별도 seed 10개로 eval 크기를 시험 생성해 얻은 범위다. 유형마다 최소 수량을 둔다. dev는 20개이고 프롬프트·형식 점검에만 쓴다. seed는 dev 3001, eval 4002다.
  - **지시문 p1(EXP-003 전용):**
    - 규칙 4를 원칙만 분명히 했다. 근거는 "문서가 그 사람의 것이라고 분명히 이어 주는 로마자 표기"뿐이고, 다른 사람의 표기는 근거가 아니며, 같은 부분에 철자가 둘이면 보류한다.
    - 형식 규칙 두 가지를 더했다. 하나는 "근거 철자를 글자 그대로", 다른 하나는 "일부 부분만 근거가 있으면 항목을 나눈다"(스키마가 항목마다 처분 하나만 받기 때문)이다.
    - MRZ·이메일·이니셜 같은 함정 유형은 나열하지 않았다. 답이 지시 안에 들어가면 EXP-002와 같은 천장이 생긴다.
    - p0의 문구와 해시는 그대로다. EXP-002 `plan.json`과 같다.
  - **근거 검사 v2(EXP-003):** 인용이 그 구간에 그대로 있어야 하는 것은 같다. 채택 표기는 단어 묶음마다 인용 안 단어열과 엄격 철자가 같아야 하고, 순서·대소문자·MRZ `<`는 무시한다. gold를 보지 않는 검사라 서비스에서도 쓸 수 있다.
  - **설정과 장치:**
    - `Settings.prompt_version`(p0/p1)과 `Settings.evidence_rule`(v1/v2)을 더한다. 실험 코드가 각 실험의 값으로 덮어쓴다(EXP-002 p0·v1, EXP-003 p1·v2).
    - 실행 장치는 `experiments/harness.py`로 옮겨 두 실험이 같이 쓴다(ADR-016).
- 선택 이유와 근거:
  - **이름 등장마다:** 99%를 통계적으로 주장할 수 있는 단위다. 한쪽 95% 하한이 0.99를 넘으려면 1,000개 중 오류 4개 이하, 500개 중 1개 이하, 300개 중 0개여야 한다[계산]. 문서 단위 정확도는 같이 보고한다.
  - **둘 다:** 안전만 보면 전부 보류해도 1.0이다. 엄격만 보면 서비스상 치명적인 오류(틀린 이름이 말없이 나감)와 비효율(근거가 있는데 보류)이 구별되지 않는다.
  - **두 단계:** 점추정 99.1%(1,000개 중 오류 9개)는 "진짜 99% 이상"의 근거가 되지 못한다. 오류가 사람·문서 단위로 몰리면 독립 가정의 하한도 실제보다 좁아서, 부트스트랩 하한을 같이 본다.
  - **원칙만:** 지시문을 그대로 두면 동명이인의 표기를 쓰는 것이 규칙 위반인지 애매해, 오류가 모델 능력 문제인지 지시 문제인지 가를 수 없다. 함정까지 나열하면 다시 답이 지시 안에 있는 시험이 된다.
  - **번역문 판정(t1)이 현재 판정 규칙을 그대로 쓰는 근거:** EXP-002 반복 1회의 C1~C3 번역문에서 보류한 이름 523건은 모두 `[A/B]` 꼴이거나 표시가 붙어 있었다(표시 없음 0, 못 찾음 0)[확인]. 그래서 C0 판정 규칙의 단어열 찾기와 표시 판정을 쓴다. 괄호 경계 너머의 표시를 옆 이름의 것으로 보지 않도록만 고쳤다.
- 비용·성능·구조에 미치는 영향:
  - **기존 동작:** 기본값(p0·v1)과 gold 형식 1에서는 동작이 그대로다. 골든 160건과 LLM 입력 해시가 바뀌지 않았고, EXP-002 `make_plan` 출력도 저장된 `plan.json`과 같다[확인].
  - **EXP-002 재개:** 재개하면 소스 해시 경고가 남는다(ADR-016). 판정 코드는 바뀌지 않았다.
  - **기록 크기:** 채점 v2는 부분별 행(`units`)을 실행 폴더 `metrics.json`에 남기고, 기록 파일(`runs.jsonl`)에는 넣지 않는다.
  - **비용:** eval 이름 부분이 계획의 약 1.2배라 비용도 그만큼 는다. 실행 전에 실제 입력 길이로 다시 추정하고 사용자 동의를 받는다.
  - **어려운 유형 비율:** 계획은 70%였으나 생성기 구조상 약 2/3(0.64~0.67)에서 멈춰 하한을 0.60으로 두었다. 나머지 1/3은 근거가 바로 옆에 있거나 아예 없는 쉬운 이름이다. 이 대조군은 엄격 정확도에서 과잉 보류를 재는 데 필요하다.
- 실행 전 수정(2026-10-21, dev 실제 모델 점검 뒤, 사용자 결정):
  - 정답 규칙과 지시문 p1은 그대로다. p1 해시도 바뀌지 않았다.
  - 생성기 v2: 문서가 p1 원칙과 정답 규칙을 서로 다르게 읽히게 하던 두 곳을 고쳤다.
    - 개인 이메일을 사람과 잇던 문의 문장
    - 파트너 번호 없는 관리자 줄
  - 생성기 v2는 B6 미달도 고쳤다. 생략 표기에 쓸 사람을 떼어 두고, 최소 수량을 못 채우면 다음 seed로 넘어간다.
  - 번역문 판정 t2: C0 표시 판정의 잘린 창 버그와, 다른 이름 자리에 걸린 후보를 고쳤다.
  - 자세한 내용은 `docs/experiments/EXP-003.md`의 "dev 실제 모델 점검"에 있다.
- 재검토 조건:
  - 확인 지점 A(dev 예시 검토)에서 정답 규칙에 이견이 나올 때.
  - dev 점검에서 긴 문서가 출력 한도에 걸릴 때.
  - 실행 뒤 사람 확인에서 채점 오류가 나올 때. 이때는 다시 채점(`exp003-rescore`)한 값을 나란히 보고하고, 판정은 사전 등록한 채점으로 한다.
  - 실제 서류 분포 자료가 생길 때.
