# ADR-017 — 어려운 시험지(synthetic-hard)와 99% 정확도 기준으로 EXP-003을 준비하고, 지시문 p1·근거 검사 v2·채점 v2를 더한다

- 날짜: 2026-10-21
- 상태: 채택. eval 생성·실행 완료(2026-10-21, ADR-020, 판정 `stop`)
- 배경: EXP-002 반복 1회(120회)에서 C1·C2·C3가 모두 만점이었다(`docs/experiments/EXP-002.md`). 시험지가 쉬운 탓으로 본다[가설]. 근거가 늘 같은 사람의 영문 줄로 바로 옆에 있고, 사람끼리 이름이 겹치지 않고, 함정이 없다. 사용자는 EXP-002 남은 240회를 보류하고, 아주 어려운 시험지를 만들고, 정확도 기준을 99% 이상으로 정했다.
- 결정: 어려운 시험지 synthetic-hard와 99% 기준(안전·엄격 둘 다)으로 EXP-003을 준비하고, 지시문 p1·근거 검사 v2·채점 v2를 더한다.
- 결정 이유:
  - 이름 부분 단위로 세야 99%를 통계적으로 주장할 수 있다. 한쪽 95% 하한이 0.99를 넘으려면 1,000개 중 오류가 4개 이하여야 한다[계산].
  - 안전만 보면 전부 보류해도 1.0이고, 엄격만 보면 치명적 오류(말없이 틀림)와 비효율(근거가 있는데 보류)이 구별되지 않는다. 그래서 둘 다 본다.
  - 점추정 99.1%는 "진짜 99% 이상"의 근거가 못 되므로 하한을 따로 본다.
  - 지시문에는 원칙만 분명히 하고 함정은 나열하지 않는다. 나열하면 다시 답이 지시 안에 있는 시험이 된다.
- 고려한 대안: (단위) 문서마다 / 인물마다. (기준) 안전만 / 엄격만. (판정) 점추정만 / 95% 하한만. (지시문) p0 그대로 / 함정 유형까지 나열. (규모) 전체 1,000개 이상 / 유형마다 500개 이상 / dev만 먼저.
- 최종 결정:
  - 99%는 이름 부분(given·father·family 등)마다 센다. 안전 정확도(말없이 틀린 이름이 나가지 않음)와 엄격 정확도(기대 처분과 정확히 일치)가 모두 0.99 이상이어야 한다. 조건 판정은 점추정으로 하고, "서비스 기준 99% 달성" 문구는 Clopper–Pearson 하한과 문서 부트스트랩 하한이 모두 0.99 이상일 때만 쓴다. 판정 구조(stop / pass / fail)는 EXP-002와 같다.
  - 엄격 철자는 대소문자·공백·하이픈·아포스트로피·MRZ `<`·연결어(bin·bint·ibn)만 무시하고, 모음·자음은 글자 그대로 같아야 한다.
  - 정답 규칙: 사람의 이름 부분마다 그 사람의 로마자 표기에 나온 완전한 철자가 하나면 확정, 둘 이상이거나 없으면 보류다. 다른 사람의 표기와 회사명·이메일·URL 속 이름은 근거가 아니다. 판단이 갈릴 수 있는 정답은 `arguable`로 표시한다.
  - 시험지: 어려운 유형 17가지(A1~D5, `docs/data.md` 5.3절), eval 70개(이름 부분 약 1,400~1,600개), dev 20개, seed dev 3001·eval 4002. 모델 결과로 문서를 고르거나 버리지 않는다.
  - 지시문 p1: 근거는 그 사람에게 분명히 이어진 로마자 표기뿐이고, 철자가 둘이면 보류하고, 근거 철자를 글자 그대로 쓰고, 일부만 근거가 있으면 항목을 나눈다. 근거 검사 v2는 엄격 철자로 대조하고 gold 없이 동작한다. `Settings.prompt_version`·`evidence_rule`은 실험 코드가 정한다. 실행 장치는 `experiments/harness.py`로 옮겨 함께 쓴다.
  - 실행 전 수정(dev 점검 뒤 사용자 결정): 생성기 v2(개인 이메일 문장, 파트너 번호 없는 관리자 줄, B6 미달), 번역문 판정 t2. 정답 규칙과 p1은 그대로다.
  - 영향: 기본값(p0·v1)에서는 동작·골든·해시가 그대로다. 어려운 유형 비율은 약 2/3(하한 0.60)이다.
  - 재검토: 사람 확인에서 채점 오류가 나올 때(`exp003-rescore` 값을 나란히 보고하고, 판정은 사전 등록한 채점으로 한다), 실제 서류 분포 자료가 생길 때.
