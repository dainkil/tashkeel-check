# ADR-011 — 제품 저장소는 Postgres + pgvector 하나로 하고, 원문 파일은 파일시스템·객체 저장소에 둔다

- 날짜: 2026-10-20
- 상태: 채택. pgvector 이전과 Qdrant 제거는 아직 하지 않음(ADR-018·022)
- 배경: 제품 저장 층이 SQLite + 파일 저장소 + Qdrant 서버 모드로 제안돼 있었다. 사용자가 배포까지 가정할 때 Postgres로 갈 수 있는지 물었다.
- 결정: 관계 데이터와 결과 JSON은 Postgres 16 하나에 두고 벡터 검색도 pgvector로 합친다. 원문 파일은 파일시스템(배포 시 객체 저장소)에 둔다.
- 결정 이유: 배포 시 동시 요청, 백업, 권한 분리, 관리형 서비스 이전이 SQLite로는 안 된다. pgvector로 합치면 컨테이너가 하나 줄고, 묶음당 조각이 수백 개 수준이라 성능 문제가 없다[가설]. 고객 단위 사전 키(ADR-010)를 UNIQUE 제약으로 강제할 수 있다. 원문을 DB에 넣으면 백업이 무거워지고 삭제 정책이 복잡해진다.
- 고려한 대안: SQLite + 파일 + Qdrant(이전 제안) / Postgres + Qdrant 유지 / 원문 파일까지 Postgres에 저장.
- 최종 결정: 결과 JSON은 JSONB로, 원문 파일은 DB에 경로와 SHA-256만 둔다. 접근은 SQLAlchemy 2 + psycopg 3, 마이그레이션은 Alembic, 로컬 개발도 Docker의 Postgres를 쓴다. 단계 1 실험의 `results/` 파일 기록은 그대로다. 재검토: 조각 수가 수만 개로 늘 때, Postgres를 쓸 수 없는 설치형 고객이 나올 때.
