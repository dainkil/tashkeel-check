# ADR-020 — EXP-003 본 실행: 참고 조건 C1p0, 단계적 반복, OpenAI flex 처리 등급

- 날짜: 2026-10-21
- 상태: 채택(코드·사전 등록까지). eval 실행은 flex 점검 뒤 사용자 확인으로 시작
- 배경과 문제:
  - EXP-003의 eval(70개, 이름 부분 1,457개)과 정답 규칙·지시문 p1·채점 v2(t2)는 고정됐다(ADR-017, `docs/experiments/EXP-003.md`).
  - 일반 호출로 반복 3회를 돌리면 약 $46(참고 조건 포함 약 $55), 동시 4개로 약 4.5시간이다[추정].
  - 사용자 결정(2026-10-21):
    - 참고 조건 C1 + 옛 지시문 p0를 넣는다.
    - 반복은 1회를 먼저 돌리고, 애매할 때만 더 돌린다.
    - 비용과 시간을 최대한 줄이고, 전체 실행은 4시간 안이어야 한다.
- 검토한 대안:
  - (비용) OpenAI Batch API(약 50% 할인, 결과가 최대 24시간 뒤) / flex 처리 등급(약 50% 할인, 바로 호출, 느리고 429 가능) / 추론 강도 낮추기 / 문서·조건 줄이기
  - (시간) 동시 실행 4 → 8 → 16
  - (반복) 3회 고정 / 1회 / 단계적
  - (참고 조건) 모든 반복 / 반복 1회만 / 넣지 않음
- 결정:
  - **참고 조건 C1p0:**
    - 조건 C1에 지시문 p0를 쓴다. 근거 검사 v2와 채점 v2는 같아서 지시문만 다르다.
    - 반복 1회에만 돌리고, 판정에는 쓰지 않는다.
    - 비교는 "C1 − C1p0"(반복 1회끼리, 문서 단위 부트스트랩)로 보고한다.
    - 코드: `exp003.REFERENCE_ARMS`·`ARM_REPEATS`·`arm`, harness `Spec.arm`, plan의 `arm_repeats`.
  - **단계적 반복(실행 전 고정):** 반복 1회가 모든 조건에서 끝나면 코드가 판단한다.
    - C1·C2·C3의 안전·엄격 정확도 점추정 6개 가운데 하나라도 [0.98, 0.995) 안이거나 값이 없으면 반복 2·3을 돈다.
    - 하나도 없으면 반복 1회로 마친다.
    - 판단은 기록 파일에 `stage` 줄(결정과 값)로 남는다. 진행 확인(`exp003-status`)에는 결정만 보인다.
    - 코드: `exp003.stage_gate`, harness `Spec.stage_after`·`stage_gate`.
  - **처리 등급:** `exp003 --service-tier flex|default`.
    - 같은 모델에 같은 요청을 보내고, 가격과 지연만 다르다.
    - 그래서 plan이 아니라 세션 기록에 남기고, 재개할 때 바꿀 수 있다(flex가 막히면 `--resume --service-tier default`).
    - 진행 표시의 비용 추정은 flex 세션의 실행에 단가 × 0.5를 쓴다[추정].
    - 이 모델이 flex를 받는 것은 짧은 호출로 확인했다(응답 `service_tier: flex`, 2026-10-21).
  - **등급 선택 규칙(실행 전 고정):**
    - flex dev 점검(v2 dev 2개 × 5조건)의 실행당 시간으로, 동시 16개일 때 반복 1~3회 최대 소요를 계산한다.
    - 3.5시간 이하면 flex를 쓰고, 아니면 기본 등급을 쓴다.
    - 속도 제한에 걸리면 동시 8개로 낮추고 다시 계산한다.
  - **동시 실행:** 16개, 속도 제한 시 8개.
- 선택 이유와 근거:
  - **Batch를 뺀 이유:**
    - 결과가 최대 24시간 뒤에 온다.
    - C2는 도구를 오가서 왕복이 2번 이상이고, 단계 판단도 반복 1회가 다 끝나야 한다. 그래서 4시간 안을 보장할 수 없다.
    - flex는 같은 수준의 할인이면서 지금 실행 장치(동시 호출, 재개)를 그대로 쓴다.
  - **추론 강도를 낮추지 않은 이유:** 출력 토큰은 줄지만, dev 점검과 다른 모델 조건이 되어 실험이 바뀐다. 99% 달성 여부를 낮게 잴 수 있다.
  - **단계적 반복:**
    - 판정은 반복을 합친 점추정이고, 99%에서 먼 결과는 반복을 더해도 판정이 바뀌지 않는다.
    - 회색 구간에서만 반복을 더하면 비용을 아끼면서, 판정이 갈릴 수 있는 곳에는 표본을 더한다.
    - 사람이 결과를 보고 멈추면 선택 편향이 생긴다. 그래서 규칙을 실행 전에 코드로 고정하고, 사람에게는 값을 보이지 않는다(ADR-016 원칙 유지).
  - **C1p0 반복 1회:** 참고 조건은 판정에 쓰지 않는다. 지시문 효과는 70문서 × 1회로 볼 수 있다.
- 비용·성능·구조에 미치는 영향:
  - **예상(dev 실측, 단가 입력 $2·출력 $10/100만 토큰, 제3자 집계 값):**
    - 기본 등급: 반복 1회(5조건) 약 $18.4, 반복 2·3회(4조건) 약 $30
    - flex: 그 절반(최대 약 $24)
    - 시간(기본 등급, 동시 16): 반복 1회 약 30분, 최대 약 1.3시간. flex는 더 느리고, 얼마나 느린지는 점검으로 잰다.
  - **service_claim:** 반복마다의 Clopper–Pearson 하한 중 가장 낮은 값을 쓰므로, 반복 1회로 끝나면 그 한 번으로 판단한다.
  - **EXP-002:** 같은 장치를 쓰지만 Spec 기본값(라벨 = 조건, 단계 없음)이라 동작과 plan이 그대로다[확인, 테스트].
  - **판정 규칙:** `judge`는 C1·C2·C3만 본다. C1p0는 `checks`에 들어가지 않는다.
- 재검토 조건:
  - flex가 실행 중 자주 막혀 기본 등급으로 바꿀 때(세션 기록에 남김).
  - 4시간 안에 끝나지 않을 것으로 보일 때. 진행 표시의 남은 시간으로 본다.

  - 테스트: `tests/test_exp003.py`
