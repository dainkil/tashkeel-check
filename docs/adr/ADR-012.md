# ADR-012 — 과제 2 요건을 단계 1.5(서비스화)로 반영하고, 제공 ZIP에서는 패턴만 가져온다

- 날짜: 2026-10-20
- 상태: 채택(2026-10-21 구현)
- 배경: 과제 2는 제공 ZIP(`all_total_vue_student`: Vue 채팅 UI, FastAPI, LangGraph, LLM 백엔드 분기, SQLite 세션, MCP 서버·클라이언트)의 구조를 재활용해 새 AI 서비스를 만들고, README·실행 화면·기능별·예외 테스트를 내라고 한다. 이 레포는 CLI 실험 장치라 웹·API·MCP가 없었다.
- 결정: 과제 2 요건을 단계 1.5(웹 화면·API·Postgres·최소 MCP)로 반영하고, ZIP에서는 패턴만 가져와 기존 구조에 다시 쓴다.
- 결정 이유: reconcile 지표와 테스트가 `AgentOutput` 스키마에 묶여 있어 ZIP 방식(httpx + JSON 모드)으로 바꾸면 검증·tool call·재시도를 다시 짜야 하고, 실험 경로와 서비스 경로가 갈라져 "같은 코드로 비교"(ADR-002)가 깨진다. `init_chat_model`이 `MODEL` 한 줄로 모델을 바꾸므로 ZIP의 백엔드 분기가 필요 없다. 채팅은 확인 대기 목록 업무 흐름과 맞지 않고, SQLite는 ADR-011의 배포 요구를 못 채운다.
- 고려한 대안: (구조) ZIP 구조를 루트에 복제 / ZIP 폴더를 그대로 고쳐 레포 코드를 import. (LLM) httpx 직접 호출 + JSON 모드 / Ollama 추가(작은 로컬 모델의 구조화 출력 안정성 [미확인]). (저장) SQLite 세션 저장소. (화면) 채팅.
- 최종 결정:
  - 기존 패키지에 `web/`·`mcp/`를 더한다. ZIP에서는 lifespan·SSE·Vue CDN 진행 표시·FastMCP stdio 클라이언트·`with_retry`·`run.sh` 골격의 패턴만 가져온다. LLM 층은 ADR-006 그대로이고, 가짜 모델은 `LLM_BACKEND=fake`로 명시할 때만 쓴다. 저장은 Postgres, 화면은 폼, 입력은 단일 문서다.
  - MCP는 툴 `analyze_tokens`, 리소스 `document://synthetic/{split}/{doc_id}`, 프롬프트 `review_instructions` 세 개를 서비스 경로에서만 쓴다. `USE_MCP_TOOLS`는 플래그로 두고 기본은 끈다.
  - 구현에서 달라진 점: C2 툴은 `build_graph(analyze_tool_factory=…)`로 바꾸고, `on_node` 콜백은 `Reviewer.run`에 두며, 번역은 `runs.result` JSONB에 둔다. ZIP 폴더는 통합 뒤 삭제했다(2026-10-21).
  - ADR-003·007의 "웹 화면·API는 단계 2"를 단일 문서 범위에서 앞당긴다. 재검토: 과제 채점이 ZIP 파일 이름·위치를 요구할 때, 구조화 출력이 불안정할 때.
