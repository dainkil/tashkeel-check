# ADR-016 — EXP-002를 멈췄다 이어서 할 수 있게 하고, 반복 → 문서 → 조건 순서로 동시에 돌리며, 중간 확인에는 사용량만 보인다

- 날짜: 2026-10-21
- 상태: 채택
- 배경: EXP-002(조건 4 × eval 30 × 반복 3 = 360회) 실행 직전에 실행 방식의 문제 다섯 가지를 확인했다.
  1. 중간에 멈추면 처음부터 다시 돌아야 했다.
  2. 조건 → 문서 → 반복 순서라 절반에서 멈추면 C2·C3가 0회였다.
  3. 돌아가는 동안 누적 토큰과 예상 총량을 볼 수 없었다.
  4. API 오류(429·인증)도 모델 실패로 기록돼, 크레딧이 떨어지면 남은 실행이 실패로 채워질 수 있었다.
  5. 순차 실행이라 약 5시간이 걸릴 것으로 보였다.

  사용자는 멈췄다 이어서 하고 사용량을 중간에 확인하며 조절하기를 원했다.
- 결정: 실행 기록 파일로 재개하고, 반복 → 문서 → 조건 순서로 동시에 돌리며, 중간 확인에는 진행과 사용량만 보인다.
- 결정 이유: 기록 파일은 산출 파일을 다 쓴 뒤 한 줄을 남기므로, 쓰다가 끊긴 실행을 완료로 보지 않는다. 반복 단위 순서면 어디서 멈춰도 네 조건이 같은 문서로 채워진다. 실행 시간 대부분이 API 대기라 동시 실행은 시간만 줄인다(가짜 모델로 결과가 같음을 확인). 중간 결과를 보고 멈출지 정하면 사전 등록한 판정이 선택적 중단으로 흔들린다.
- 고려한 대안: (재개) 실행 폴더의 `metrics.json` 유무로 판단. (시간) Batch API(C2 툴 루프와 맞지 않고 느림) / 추론 강도 낮추기(모델 조건이 바뀜) / 반복 3 → 2(사용자가 확정한 규모) / 로컬 모델(16GB Mac에서 8B급이라 아랍어·스키마 출력이 약할 것[가설]). (중간 확인) 결과 지표까지 보임.
- 최종 결정:
  - 재개: `plan.json`(문서 해시·조건·반복·순서·모델·설정·프롬프트 해시·버전)을 처음 한 번 고정하고, 실행마다 `runs.jsonl`에 한 줄을 남긴다(fsync). `--resume`은 기록에 없는 실행만 돌리고, 설정이 다르면 이어 붙이지 않는다. 세션마다 git 커밋과 소스 해시를 기록한다.
  - 동시 실행은 `--workers`(첫 실행 4). `--max-runs`, `--token-budget`, `STOP` 파일, 첫 Ctrl+C 가운데 하나가 걸리면 돌던 실행만 마저 기록하고 멈춘다(종료 코드 4).
  - API 오류로 출력이 없으면 완료로 치지 않고 멈춘 뒤, 재개할 때 다시 돌린다.
  - `exp002-status`는 진행·토큰·실패 수·예상 총량만 보인다. 비율 지표와 판정은 완료 뒤 `summary.json`에만 나온다. 비용 때문에 그만둘 때만 `--finalize`로 부분 결과를 쓴다.
  - 영향: 그래프·채점·판정 코드와 골든은 그대로다. 동시 4개면 360회가 약 1.4~1.9시간이다[추정]. 예산 제한은 최대 workers − 1개만큼 넘칠 수 있다.
  - 재검토: 429로 자주 멈출 때, 반복 회차 사이 결과가 체계적으로 다를 때.
