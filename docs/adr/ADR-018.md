# ADR-018 — 서류 묶음 검수는 대상 ID로만 같은 대상을 판단하고, 정확 일치일 때만 확정하며, 사전 키에 대상 ID를 더한다

- 날짜: 2026-10-21
- 상태: 채택(구현)
- 배경과 문제: 사용자가 14단계 개발 가이드(환경 → 데이터 읽기 → 이름 추출 → 근거 검색 → 판정 → 저장 → API → LLM → 형태소 분석 → RAG → MCP → 멀티 에이전트 → 화면·평가)를 가져와 계획을 다시 세우라고 했다. 가이드의 핵심은 서류 묶음 안에서 같은 대상의 다른 서류를 근거로 찾아 인용을 검증하고, 근거가 없거나 충돌하면 확인 대기로 돌리는 흐름이다. 레포에는 단일 문서 검수(C0~C3)와 단계 1.5 서비스(API·Postgres·화면·MCP)가 있었고, 묶음 검색 틀(`rag/bundle.py`, ADR-007)은 **아랍어 표기가 같으면** 다른 서류의 줄을 찾아 주는 방식이라 같은 이름의 다른 대상(동명이인, 같은 이름의 다른 회사)을 근거로 쓸 위험이 있었다. 가이드는 또 저장소를 SQLite로 시작하라 하고, 확정된 표기를 사전에 자동 등록하라고 한다. 이 셋을 레포의 기존 결정(ADR-010·011)과 맞춰야 했다.
- 사용자 결정(2026-10-21): 새 `app/` 프로젝트를 만들지 않고 이 레포에 가이드 개념을 얹는다. EXP-002는 120/360에서 보류한다. 단계 1.5를 기준으로 하되 가이드에서 고칠 구석을 반영한다. 저장은 Postgres 유지. 멀티 에이전트(가이드 13단계)는 하지 않는다. 사람 이름에 치중하지 않고 고유명사 범위를 명시한다.
- 검토한 대안:
  - (같은 대상 판단) 데이터가 준 대상 ID로만 / 아랍어 표기 정규화 키가 같으면 같은 대상 / 벡터 유사도.
  - (확정 비교) 대소문자·공백만 무시한 정확 일치 / `romanize.match_spelling`(같은 독법의 변이 허용, EXP-001 규칙 v1).
  - (사전) ADR-010 그대로(사람이 보류를 닫을 때만 등록, 키 = 고객 + 정규화 아랍어) / 가이드대로 확정 항목 자동 등록 / 키에 대상 ID 추가.
  - (저장) SQLite 먼저 / Postgres 유지.
  - (구조) 가이드의 `app/` 파일 구조로 새로 / 레포의 `src/tashkeel_check/bundle/` 패키지로.
- 결정:
  - **같은 대상 여부는 묶음 데이터의 `entity_id`로만 판단한다.** 근거는 같은 묶음의 **다른 서류**에서 같은 `entity_id`가 붙은 구간의 영문 칸이다. 아랍어 표기가 같아도 ID가 다르면 쓰지 않는다. ID가 없는 고유명사는 근거를 찾지 않고 "대상 ID 없음"으로 대기에 올린다. 기존 `BundleIndex`는 `from_documents(..., entity_id=…)`로 같은 대상 구간만 색인하는 후보 힌트로만 두고 근거 출처로 쓰지 않는다.
  - **고유명사 범위:** 대상 ID가 붙은 모든 명명 대상(개인, 회사·법인, 기관·단체, 그 밖의 당사자)을 같은 규칙으로 다룬다. 종류(`person` / `organization` / `other`)는 표시·집계용이다. 근거 서류의 종류는 제한하지 않는다(신분증·여권·상업등기·정관·이전 계약서·공문 등). 어느 서류를 더 믿을지는 정하지 않고, 서류끼리 다르면 무조건 대기다. 단일 문서 경로의 범위와 동작은 바꾸지 않는다. 전체 표는 `docs/scope.md` "정한 것 (2026-10-21, 가이드 반영)".
  - **확정은 정확 일치일 때만이다.** NFC·casefold·공백 정리 뒤 같아야 하고 원래 표기는 보존한다. 공식 서류의 영문 표기는 그대로 써야 하므로 `Mohammed`/`Mohamed`, `Co.`/`Company`는 다른 표기다. `match_spelling`은 제안(`suggestion`)에만 쓴다. `reconcile.verify_evidence`(단일 문서 경로, 변이 허용 `spelling_in_text`)와 다른 점은 의도한 것이다.
  - **판정 순서(가이드 6단계 규칙 6개 + 2개):** 추출 실패 → 대상 ID 없음 → 유효 근거의 정규형이 둘 이상이면 "서류 간 표기 충돌" → 유효 근거 있음: 번역 표기 없음 "비교 대상 없음" / 일치 "근거 일치"(확정) / 불일치 "번역 표기 불일치" → 근거는 있으나 전부 검증 실패면 "검증 실패" → 근거 없고 사전 적중이면 "사전 일치"(확정) 또는 불일치 → "근거 없음". 사전은 근거를 이기지 못하고, 사전과 근거가 다르면 충돌이다.
  - **사전(ADR-010 보완):** 키는 고객 ID + **대상 ID** + 정규화 아랍어 표기다. 등록은 사람이 확인 대기 항목을 닫을 때만 한다(`POST /v1/dictionary`). 가이드의 "확정 항목 자동 등록"은 채택하지 않는다(`review_bundle(auto_register=False)` 옵션만 두고 기본 off). `customer_id`가 없는 묶음은 사전을 보지 않는다.
  - **저장:** Postgres 유지(ADR-011). 표 3개(`bundles`, `review_items`, `name_dictionary`)를 Alembic 0002로 더한다. `DATABASE_URL`이 없으면 메모리 저장소로 돌아 가이드 1~8단계가 DB 없이도 된다.
  - **구조:** `src/tashkeel_check/bundle/`(schemas, loader, extractor, evidence, rules, dictionary, pipeline). 라벨 칸(`الاسم:`, `اسم الشركة:`, `الجهة:` …, `Name:`, `Company Name:` …)에서 LLM 없이 뽑는 결정적 경로가 기본이고, 라벨 칸이 없는 문장은 기존 LLM 경로(C1~C3)가 뽑아 같은 판정 함수를 탄다. 묶음 검수 API는 동기(`POST /v1/bundles/review`), LLM 경로는 서류별 작업(`POST /v1/bundles/{id}/reviews`)이다. API 호출 실패는 `model_error`(실행 오류)로 이름 미검출과 구분한다(`exp002.is_api_failure` 재사용).
  - 가이드의 `app/` 파일 구조와 SQLite, 멀티 에이전트(13단계)는 따르지 않는다. 가이드의 평가 사례 9개는 합성 묶음 생성기(`data/bundles.py`)가 대상 종류 3개마다 만든다.
- 선택 이유와 근거: KYC 묶음에서 신분증·등기의 영문 표기는 법적 표기라 변이를 같다고 보면 오확정이 되고, 그 오확정이 사전에 굳으면 다음 묶음으로 번진다(ADR-010의 이유). 이름이 같다는 사실은 같은 대상이라는 근거가 아니다(가이드 4단계 원칙). 대상 ID는 고객이 묶음을 접수할 때 아는 정보이므로 데이터에 요구할 수 있다. 종류별로 규칙을 달리할 이유가 없고, 합성 사례를 종류마다 돌려 결과가 같음을 테스트로 고정했다(`tests/test_bundle_eval.py`).
- 비용·성능·구조에 미치는 영향: 단일 문서 경로·실험·골든 테스트·LLM 입력 해시는 바뀌지 않았다(372개 통과, 골든 160건 그대로). 라벨 경로는 LLM 호출이 없어 비용 0이다. `rag/bundle.py`의 `BundleHit`에 `document_id`·`segment_id`가 더해졌고, MCP 서버에 `search_bundle` 툴과 묶음 리소스가 더해졌다. 로드맵 2.5의 `glossary(customer_id, arabic_key)`는 `name_dictionary(customer_id, entity_id, arabic_key)`로 바뀐다. `name_items`에 `evidence_document_id`를 더했다. 서류 우선순위, 사람 검토 상태 관리, pgvector 이전, 다른 고객 간 공유는 범위 밖이다.
- 재검토 조건: 실제 묶음에서 대상 ID를 붙일 수 없는 비율이 높을 때(이름 기반 후보 연결을 "제안"으로 승격 검토). 정확 일치가 너무 엄격해 같은 서류의 표기 차이(공백·구두점)로 대기가 과다할 때. 서류 종류별 우선순위가 필요해질 때.
- 관련 코드·실험·트러블슈팅: `bundle/`, `data/bundles.py`, `web/bundles.py`, `web/bundle_jobs.py`, `web/app.py`(`/v1/bundles/*`, `/v1/dictionary`), `web/models.py`·`alembic/versions/0002_bundles.py`, `mcp/server.py`(`search_bundle`), `rag/bundle.py`(`from_documents`), 테스트 `tests/test_bundle_*.py`, `docs/과제2-테스트-기록.md` 5절.
- 대체하거나 대체된 ADR: ADR-010을 보완한다(사전 키에 대상 ID 추가, 등록 정책은 그대로). ADR-007의 묶음 검색 틀을 "근거 출처"에서 "후보 힌트"로 낮춘다. ADR-011(Postgres)·ADR-012(단계 1.5)는 그대로다. ADR-017(다른 세션의 synthetic-hard·EXP-003)과는 독립이다.
