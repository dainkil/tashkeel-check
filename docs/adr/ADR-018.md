# ADR-018 — 서류 묶음 검수는 대상 ID로만 같은 대상을 판단하고, 정확 일치일 때만 확정하며, 사전 키에 대상 ID를 더한다

- 날짜: 2026-10-21
- 상태: 채택(구현). 추가 개발은 ADR-021로 보류
- 배경: 사용자가 14단계 개발 가이드를 가져와 계획을 다시 세우라고 했다. 가이드의 핵심 흐름은 서류 묶음 안에서 같은 대상의 다른 서류를 근거로 찾아 인용을 검증하고, 근거가 없거나 충돌하면 확인 대기로 돌리는 것이다. 기존 묶음 검색 틀(ADR-007)은 아랍어 표기가 같으면 다른 서류의 줄을 찾아 줘서 동명이인을 근거로 쓸 위험이 있었다. 가이드는 SQLite로 시작하고 확정 표기를 사전에 자동 등록하라고 했다.
- 결정: 묶음 검수는 데이터의 대상 ID(`entity_id`)로만 같은 대상을 판단하고, 영문 표기가 정확히 일치할 때만 확정하며, 사전 키에 대상 ID를 더한다.
- 결정 이유: KYC 묶음의 신분증·등기 영문 표기는 법적 표기라 변이를 같다고 보면 오확정이 되고, 그 오확정이 사전에 굳으면 다음 묶음으로 번진다. 이름이 같다는 사실은 같은 대상이라는 근거가 아니다. 대상 ID는 고객이 묶음을 접수할 때 아는 정보라 데이터에 요구할 수 있다.
- 고려한 대안: (같은 대상) 아랍어 정규화 키 / 벡터 유사도. (확정 비교) `match_spelling`의 변이 허용. (사전) 가이드대로 확정 항목 자동 등록. (저장) SQLite 먼저. (구조) 가이드의 `app/` 구조로 새로 만들기.
- 최종 결정:
  - 근거는 같은 묶음의 다른 서류에서 같은 `entity_id`가 붙은 구간의 영문 칸뿐이다. ID 없는 고유명사는 "대상 ID 없음"으로 대기에 올린다. 개인·회사·기관·기타를 같은 규칙으로 다루고, 서류끼리 다르면 무조건 대기다(서류 우선순위 없음).
  - 확정은 NFC·casefold·공백 정리 뒤 정확히 같을 때만이다. `match_spelling`은 제안에만 쓴다.
  - 판정 순서: 추출 실패 → 대상 ID 없음 → 서류 간 표기 충돌 → 근거 일치(확정) / 번역 표기 불일치 / 비교 대상 없음 → 검증 실패 → 사전 일치(확정) / 불일치 → 근거 없음. 사전은 근거를 이기지 못한다.
  - 사전 키는 고객 ID + 대상 ID + 정규화 아랍어다. 등록은 사람이 대기 항목을 닫을 때만 한다(ADR-010).
  - 저장은 Postgres(표 3개, Alembic 0002), 코드는 `src/tashkeel_check/bundle/`이다. 라벨 칸에서 뽑는 결정적 경로가 기본이고, 라벨 없는 문장은 LLM 경로(C1~C3)가 뽑아 같은 판정 함수를 탄다.
  - 같은 날 보완: 여권 성·이름 칸 합성과 MRZ 해독(같은 서류에 인쇄 칸이 있으면 MRZ 제외), 파일 업로드 `POST /v1/bundles`, 묶음 SSE, 합성 KYC 묶음(사례 8개 × dev·eval).
  - 영향: 단일 문서 경로·실험·골든·해시는 그대로다. `BundleIndex`는 근거 출처에서 후보 힌트로 낮춘다(ADR-007).
  - 재검토: 대상 ID를 붙일 수 없는 비율이 높을 때, 정확 일치가 너무 엄격해 대기가 과다할 때, 서류 우선순위가 필요할 때.
