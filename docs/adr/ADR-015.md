# ADR-015 — EXP-001 개발용 표본에서 표기 일치·정렬 규칙을 v1로 고쳐 고정하고, dev 분할을 키 목록으로 고정하며, 합성 문서를 다시 만든다

- 날짜: 2026-10-20
- 상태: 채택
- 배경: EXP-001은 dev 300개로 정렬·일치 규칙을 고친 뒤 고정하고 main을 한 번 재도록 사전 등록했다([6.1절](../evaluation.md)). dev에서 세 문제가 드러났다.
  1. 일치 규칙 v0는 5자 이상이면 편집 거리 1을 같은 이름으로 봐서, Hajjaj ↔ hujaj처럼 모음이 다른 독법이 일치로 들어갔다(약 16건).
  2. 영문 표기 관례(Abdul, th·dh, o·ou, -eh, aal)를 놓쳤다.
  3. 정렬이 라틴 문자 레이블과 한쪽에만 접두가 있는 별칭을 받아들였다.

  M5(0.58)가 기준선 0.5에 가까워 이 오차가 판정을 바꿀 수 있었다. 또 dev·main 분할이 위치로 정해져 있어, 규칙을 바꾸면 이미 본 dev 단위가 main으로 넘어갈 수 있었다.
- 결정: 표기 일치·정렬 규칙을 v1로 고쳐 고정하고, dev 분할을 키 목록으로 고정하며, 합성 문서를 synthetic-v2로 다시 만든다.
- 결정 이유: 독법 차이는 모음 차이인데, 편집 거리는 모음과 자음을 구별하지 않아 측정 대상을 지운다. 영문 e는 a·i·u 셋 다 될 수 있어(Ahmed, Hamed, Yousef) 펼쳐야 흔한 표기를 놓치지 않는다. 키 목록으로 고정하면 규칙을 바꿔도 dev 구성이 그대로다. eval로 아무것도 돌리지 않아 합성 문서를 다시 만드는 비용이 낮다.
- 고려한 대안: (일치) 편집 거리에 예외만 추가 / 편집 거리 없이 정규화만. (분할) 위치 기반 유지 / 키 해시 임계값. (합성 문서) 잘못된 짝을 알려진 잡음으로 적고 유지. 아인 양옆 모음을 합치지 않는 규칙도 시험했지만 Al Zaabi ↔ al-za'abiyy 같은 흔한 표기를 놓쳐 버렸다.
- 최종 결정:
  - 일치 규칙 v1: 관사·하이픈·아포스트로피를 걷고, Abdul·Abdel·Abdur는 abd로 줄인다. 영문 e는 a·i·u로, o·ou는 u·aw로 펼친다. th·dh·z·d는 한 부류, q = k(방언 옵션은 q ↔ g)로 보고, 겹글자를 접고, ay → ai, 끝 -iyy → -i, 끝 -ah → -a로 둔다. 정규형이 같으면 일치이고, 아니면 대표형끼리 자음 하나 또는 y ↔ i·w ↔ u 하나만 다를 때 일치다(4자 이상). 정렬 규칙 v1은 [5.1절](../data.md).
  - dev는 v0 단위 목록의 seed 7 앞 300개 키를 `data/wikidata/exp001_dev_keys.json`에 고정한다.
  - 영향: EXP-001 dev M5가 0.58에서 0.587(엄격)·0.591(방언 허용)이 됐다. `match_spelling`을 쓰는 EXP-002 채점과 묶음 검색에도 적용된다. 골든 160건은 `matcher_version`만 바뀌었다. 합성 문서는 이름이 바뀐 것이 dev 8개·eval 21개이고, 근거 배치와 개수는 그대로다.
  - 재검토: main 측정 뒤 오일치 표본을 사람이 볼 수 있을 때, 다른 지역 표기 관례가 많은 문서를 잴 때, e 펼침이 보류 후보 적중률을 부풀린다는 근거가 나올 때.
