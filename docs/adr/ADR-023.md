# ADR-023 — 제품을 "실시간 아랍어 TTS의 이름 발음 앞단 층"으로 전환하고, 서류 검수 경로는 코드만 남겨 보관한다

- 날짜: 2026-10-23
- 상태: 채택(계획). ADR-021·022의 제품 정의(서류 검수)를 대체. ADR-001(음성 모음 검수 → 서류 검수)과 연결되지만 되돌리는 것은 아니다(아래 "ADR-001과의 관계"). 코드는 아직 바뀌지 않았다.
- 배경: 제출본(2026-10-22)은 아랍어 서류의 이름을 영문 표기 후보와 근거로 보여 주는 검수 서비스였다. 2026-10-23에 "실제 제품 수준으로 올리는 방향"을 조사하던 중 사용자가 방향을 TTS로 바꾸기로 했다. 이 레포의 핵심 자산은 영문 표기가 아니라 **"근거 없는 독법은 확정하지 않고, 근거와 확정 기록을 쌓는 장치"**이고, 아랍어 TTS의 가장 약한 지점이 같은 자리(단모음이 없는 고유명사의 발음)다. 조사 결과 디아크리타이저(CATT·Sadeed)와 LLM(GPT-4o, NYUAD 고유명사 벤치 73%)은 고유명사에서 가장 약하고, 신경망 TTS는 저자원 고유명사를 체계적으로 틀리게 읽으며(SonoEdit 2026), 최신 오픈 엔진(Habibi 2026)은 디아크리틱스 없이 합성하는 쪽으로 가고 있어 이름 발음을 엔진 밖에서 제어할 필요가 커진다([조사 기록](../research/tts-literature.md)).
- 결정: 제품을 "아랍어 음성 에이전트가 말할 텍스트의 고유명사(사람·회사·지명)마다 올바른 독법을 근거와 함께 정해 TTS 엔진에 넘기는 앞단 층"으로 바꾼다. 1차 용도는 실시간 음성(콜센터 봇·대화형 에이전트), TTS 엔진은 기존 것을 쓰고(자체 학습·파인튜닝 없음), 서류 검수 경로는 코드·테스트·골든만 남기고 문서는 보관한다.
- 결정 이유:
  - 사용자 결정(2026-10-23): 용도는 실시간 음성, 기존 제품은 완전 전환, 범위는 앞단 층만.
  - 핵심 약속("확인해야 할 이름을 빠뜨리지 않고 근거와 함께 알려 준다")과 설계 원칙(보류는 코드가 결정, 인용은 코드가 검사, 사전은 사람만 쓴다)이 그대로 옮겨간다. 실시간에서는 "보류"가 "기본 독법 + 낮은 확신 표시 + 사후 확정"으로 바뀐다.
  - 시장 공백: 아랍어 콜센터 TTS 벤더는 자동 디아크리타이저로 읽고, 이름 발음 전문 제품(NameCoach 등)은 영어 중심이다. "이름 독법 결정 + 근거 + 고객 사전 + 엔진별 출력 + 측정"을 묶은 것은 조사에서 찾지 못했다 [문헌○, 제한된 검색].
  - 코드 재사용: 토큰·구간 ID(`text.py`), `normalize_key`(디아크리틱스 제거 → 사전 키), CAMeL `diac` 후보, 사전 저장소와 API, 범위 토큰 MCP, 실험 장치(`harness.py`), 설계 원칙이 그대로 쓰인다. 영문 표기에 묶인 부분(스키마·근거 검사·중재자 비교·프롬프트·채점기)은 바꾼다([architecture.md](../architecture.md) 재사용 표).
- 고려한 대안:
  - **사전 제작 음성(IVR 안내·공지) 우선.** 보류가 그대로 작동하고 측정이 쉽다. 사용자가 실시간을 골랐다. 사전 제작은 같은 사전을 쓰는 하위 경로로 남긴다.
  - **두 제품 유지(서류 검수 + TTS).** 문서·테스트 유지 비용이 두 배다. 사용자가 완전 전환을 골랐다.
  - **오픈 TTS 모델 파인튜닝까지.** GPU·음성 데이터·평가 인력이 필요하고 걸프 방언 TTS 데이터가 얇다(ArVoice가 MSA 100시간 미만). 사용자가 앞단 층만을 골랐다.
  - **옛 음성 모음 검수 계획(ADR-001 이전)으로 복귀.** 그 계획은 학습 데이터 검수(배치, 음성 + 전사)였고 구매자를 찾지 못했다. 이번은 실시간 발화 텍스트의 고유명사 발음 결정이라 고객·흐름이 다르다.
- 최종 결정:
  - **제품 정의와 목표**는 [problem-and-goals.md](../problem-and-goals.md), **범위**는 [scope.md](../scope.md), **구조**는 [architecture.md](../architecture.md)에 둔다. 두 경로: 오프라인(후보 생성·근거 검사·사람 확정 → 고객 발음 사전)과 실시간(`/v1/pronounce`: 사전 조회 + 결정적 디아크리타이저 + 엔진 형식 치환, LLM 없음, 목표 p95 50ms 이하 [제안]).
  - **확정 규칙**: 사전에 들어가는 독법은 사람 확정, 본인 녹음 정렬 통과, 등록 서류·CRM의 라틴 표기 일치 중 하나의 근거가 있을 때만. 디아크리타이저·LLM 출력은 "기본 독법"이고 확정이 아니다. 자음 골격이 바뀐 출력은 폐기한다.
  - **첫 실험**은 EXP-006(엔진 베이스라인: 걸프 인명을 엔진이 얼마나 틀리게 읽는가, 디아크리틱스·phoneme·사전을 주면 얼마나 고쳐지는가, 엔진이 그 입력을 존중하는가). 사전 등록은 [EXP-006](../experiments/EXP-006.md), 지표는 [evaluation.md](../evaluation.md).
  - **보관**: 서류 검수 기준 문서 6개와 실험 요약은 [docs/archive/document-review/](../archive/document-review/)에 복사했다. `deploy.md`·`과제2-테스트-기록.md`·실험 기록 EXP-001~003·ADR·troubleshooting·changelog는 현재 코드를 설명하므로 제자리에 둔다. 코드(`graph.py` C0~C3, `multi_agent*.py`, `archive*`, 업로드 화면, OCR, 묶음 검수)와 테스트 559개·골든 160건은 그대로다.
  - **영향**: 코드 변경 없음. README·PROJECT_PLAN·AGENTS·문서 지도를 TTS 기준으로 다시 썼다. 측정값은 없다(EXP-006 미실행). 서류 검수의 측정값(C1 엄격 0.9993)은 보관 문서에만 남고 새 제품의 성능 주장에 쓰지 않는다.
  - **재검토 조건**: EXP-006에서 주요 엔진이 디아크리틱스 없이도 걸프 인명을 95% 이상 맞게 읽으면 앞단 층의 가치를 다시 본다. 실시간 지연 목표를 결정적 경로로 맞출 수 없으면 사전 제작 음성 우선으로 돌린다. 녹음 수집이 PDPL·동의 때문에 어려우면 근거를 라틴 표기·사람 확정 둘로 줄인다.
- ADR-001과의 관계: ADR-001은 "음성 근거 기반 모음 검수(TTS 데이터 팀용, 배치)"를 버리고 서류 검수로 갔다. 이번 결정은 TTS 영역으로 돌아가지만 대상(실시간 발화의 고유명사)·고객(음성 봇 운영자)·흐름(앞단 층)이 다르다. 옛 계획의 문헌(Shatnawi 2024, Marew 2026 격자 제약 디코딩, KSAA-2026, 설계 원칙 "자음 골격 불변·닫힌 후보 집합·제안과 판정 분리")은 다시 쓴다(`git show f3d70cf:PROJECT_PLAN.md`).
