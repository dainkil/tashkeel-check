## 5.3 자체 라벨: 걸프 인명 디아크리틱스 200개 [제안]

- **표본:** Wikidata 걸프 인명 풀에서 이름 위치(이름·아버지 이름·가문명) 비율을 맞춰 200단위. 영문 변이가 2개 이상인 단위를 절반 이상 넣는다(모호한 경우가 측정 대상).
- **라벨:** 아랍어 원어민 라벨러 2인이 독립적으로 완전 디아크리틱스(격어미 제외)와 걸프 방언 독법(ق→g 등)을 단다. 불일치는 둘 다 기록하고 `arguable`로 둔다. 라벨러 간 일치율(DER·단위 정확 일치)을 보고한다. 사람 간 불일치가 정확도 상한이다(Bouamor 2015: WER 1.6~5.6% [문헌○]).
- **형식:** `{arabic, diacritized_msa, diacritized_gulf?, english_variants, position, labeler_agreement, notes}`.
- **분할:** dev 50(디아크리타이저·규칙 조정용)·eval 150(EXP-006 한 번만). eval은 조정에 쓰지 않는다.
- **라벨러 [미확인]:** 팀 안에 아랍어 검수자가 없다(ADR-008 때부터). 외주 또는 협력 없이는 이 세트를 만들 수 없다. 그 경우 EXP-006은 CamelProp만으로 돌리고 걸프 방언 독법은 재지 않는다고 적는다.

## 5.4 합성 발화 생성기 v1 [제안]

- **목적:** 실시간 경로의 이름 탐지·지연·치환 테스트. 발음 정답이 아니라 "이름이 어디 있고 어떤 형식으로 치환돼야 하는가"의 정답.
- **템플릿:** 콜센터 발화 유형(인사·본인 확인·잔액 안내·예약 확인·거래처 언급·지점 안내) × 이름 자리(호칭 뒤, 문장 처음, 소유격, 회사명 안). 이름은 5.1 풀, 회사·지명은 고정 목록.
- **정답:** 이름 토큰 ID, 기대 확신 등급(사전에 넣은 것은 high), 기대 치환 형식(엔진별).
- **분할·seed:** dev·eval을 다른 seed로. 서류 검수 생성기(`data/synthetic_hard.py`)의 결정적 생성·수량 보고 방식을 따른다.
- **한계:** 아랍어 문장의 자연스러움은 사람이 검수하지 않는다. 지연·탐지만 재고 발음 정확도에 쓰지 않는다.

## 5.6 고객 데이터 (데이터셋 아님)

- 고객 발음 사전, 발화 로그, 확정 큐, 녹음은 서비스가 실행 중에 쌓는다. 고객 범위로만 조회한다.
- 녹음은 역내 저장, 동의 기록, 파생 독법(디아크리틱스·음소열)만 보관을 기본으로 한다. 원본 보관은 설정이고 기본은 끈다 [제안]. 사우디 PDPL은 생체 데이터를 민감 정보로, UAE 45/2021은 음성을 식별자로 본다 [문헌○].
- 운영 측정(3단계)은 저확신 발화 표본과 자동 확정 무작위 표본을 사람이 듣는 방식이다. 이 표본은 고객 동의 범위 안에서만 쓴다.
