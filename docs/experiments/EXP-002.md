# EXP-002 — 조건 C0~C3 비교 (Q1~Q3)

> 요약은 [실험 기록 README](README.md)에 있다. 이 문서는 사전 등록·실행 방식·중간 값의 상세 기록이다.

- 상태: **보류** (120/360회, 반복 1회 완료. 2026-10-21 사용자 결정으로 멈추고 EXP-003으로 넘어감. 판정 없음)
- 확인할 질문: Q1 에이전트가 말없이 찍는가(C0), Q2 지시만으로 해결되는가(C1 대 C0), Q3 분석기를 주면 더 잡는가(C2·C3 대 C1)
- 데이터: 합성 평가 문서 `data/synthetic/eval/` 30개(seed 2002, 생성기 synthetic-v2). 개발 문서 10개(seed 1001)는 프롬프트 디버깅에만 쓴다. eval의 근거 배치는 없음·일부 역할만·전부 각 10개, 근거 없는 이름 61개(토큰 174개)가 문서 20개에 있다
- 규모(사용자 확정): 조건 4 × 평가 문서 30 × 반복 3 = 360회
- 모델: `openai:gpt-6.1-sol`(`.env`의 `MODEL`), 모든 조건에 같은 모델

## 실행 전에 고정한 것 (2026-10-13)

- 정답 기준: 고유명사가 나올 때마다, 문서 안에 영문 표기가 있으면 기대 처분은 근거 채택(인용), 없으면 보류
- 주 지표: 근거 없는 고유명사 토큰 가운데 표시도 보류도 없이 하나로 옮긴 비율(말없이 찍음)
- 보조 지표: 몰래 정함(2026-10-20 추가, 판정에 씀), 근거 없는 확정, 보류율, 근거 채택 검증 통과율, 근거 검증 실패, 미처리, 과잉 표시, 고확신 무근거 확정(**확신도 ≥ 0.8**, 사용자 확정), 표기 불일치, 도구 사용, 비용, 반복 간 범위
- C0 판정 규칙 v0(`reconcile._marked`). 실행 후 자동 판정 20건을 사람이 확인한다
- 비율은 문서별 평균이 아니라 개수를 합쳐 계산한다. 반복 간 범위와 문서 단위 부트스트랩 95% 구간을 같이 낸다

## 실행 전 변경 (2026-10-20, ADR-014)

M0 점검 실행(dev 문서 2개, synthetic-v0)에서 채점 정의 문제가 드러나 실행 전에 고쳤다. eval로는 어떤 모델도 돌리지 않았다.

- 미처리: 이름 미처리(`n_unprocessed_names`)를 G1 지표로, 일반 단어 미처리(`n_unprocessed_ambiguous_words`)를 보조로 둔다. 모호 판정 규칙 자체는 LLM 입력이라 바꾸지 않았다
- 중립 토큰(지명·국가명·발급 기관·법인 형태)은 미처리·근거 없는 확정·과잉 표시에서 뺀다
- 과잉 표시와 근거 없는 확정을 토큰 단위로 센다(`n_over_flag_tokens`, `n_unsupported_adopt_tokens`, `n_high_conf_unsupported_tokens`). 한 토큰을 여러 항목이 덮으면 고유명사 항목을 대표로 판정한다
- 보조 지표 추가: 보류 후보 적중률(`hold_candidate_hit_rate`, 보류 항목의 후보에 실제 표기가 든 비율)
- 합성 문서를 synthetic-v1로 다시 만들었다(위 데이터 줄). 이전 v0은 eval 30개 중 18개가 근거 전부, 12개가 없음이었고 섞인 문서가 없었다
- 집계: 조건에 없는 지표(C0의 보류율 등)는 0.0이 아니라 None으로 낸다

## 실행 전 변경 (2026-10-20, ADR-015)

EXP-001 dev에서 표기 일치 규칙을 v1로 고쳤다. 이 규칙은 채점에도 쓰인다(근거 인용 검사, 보류 후보 적중, C0 표기 찾기, 표기 일관성). 이제 모음이 다른 표기는 같은 이름으로 보지 않는다(v0는 5자 이상이면 편집 거리 1을 허용했다).

- 같은 dev 문서로 골든을 다시 만들어 비교하니 160건 모두 `matcher_version`만 바뀌었다
- 이름 풀을 정렬 규칙 v1로 다시 만들고 합성 문서를 synthetic-v2로 다시 생성했다. synthetic-v1 eval에는 v1에서 걸러지는 정렬 짝이 정답 표기로 4토큰 들어가 있었다(إبراهيم ↔ Abu Aws 등). 근거 배치와 구성 개수는 그대로다
- eval로는 여전히 어떤 모델도 돌리지 않았다

## 실행 방식 변경 (2026-10-21, ADR-016)

사용자 요청("중간에 멈춰도 재개 가능하게, API 사용량을 중간중간 확인하며 조절")에 따라 실행 장치를 바꿨다. 규모·지표·합격선·중단 기준은 그대로다.

- 재개: 실행 폴더에 `plan.json`(문서 해시·조건·반복·순서·모델·설정·프롬프트 해시·일치 규칙·분석기 버전)을 고정한다. 실행마다 `runs.jsonl`에 한 줄을 남긴다. `--resume`은 남은 실행만 돌리고, 설정이 다르면 거부한다
- 순서: 조건 → 문서 → 반복에서 **반복 → 문서 → 조건**으로 바꿨다. 반복 1회(120회)마다 네 조건이 같은 문서로 채워진다
- 동시 실행: `--workers 4`(사용자 결정). 결과는 순차 실행과 같다(가짜 모델로 확인)
- 멈춤: `--max-runs`, `--token-budget`, 실행 폴더의 `STOP` 파일, Ctrl+C. 돌던 실행만 마치고 멈춘다
- API 오류: 출력을 못 얻었고 원인이 openai 오류면 그 실행을 완료로 치지 않고 바로 멈춘다. 재개하면 다시 돈다. 모델의 형식 실패는 지금처럼 결과로 센다
- 중간 확인: `uv run tashkeel exp002-status`에는 진행·토큰·형식 실패·재시도·API 오류·예상 총량만 나온다. 비율 지표와 판정은 완료 뒤 `summary.json`에만 나온다(사용자 결정, 선택적 중단 방지). 비용 때문에 그만둘 때만 `--finalize`로 부분 결과를 쓰고 `complete: false`로 표시한다

## dev 점검 (2026-10-21, 실제 모델)

사용자 결정("먼저 dev 점검")으로 eval 전에 dev_001(synthetic-v2)을 C0~C3 각 1회, 동시 4개로 돌렸다. C0·C3를 실제 모델로 돌린 것은 처음이다. eval로는 여전히 아무것도 돌리지 않았다.

- 명령: `uv run tashkeel exp002 --split dev --limit 1 --repeats 1 --workers 4 --yes`, 결과 `results/exp002/dev/20261021T001207Z/`
- 네 조건 모두 첫 시도에 형식 통과(`valid_output`, 재시도 0, 11구간 모두 번역, API 오류 0) [확인]. C0 출력은 구간 라벨이 붙은 실제 번역문이다

| 조건 | 입력 토큰 | 출력 토큰 | 합계 | LLM 호출 / 툴 호출 | 시간 |
| --- | --- | --- | --- | --- | --- |
| C0 | 324 | 266 | 590 | 1 / 0 | 6초 |
| C1 | 1,416 | 4,843 | 6,259 | 1 / 0 | 77초 |
| C2 | 7,632 | 5,361 | 12,993 | 2 / 1 | 93초 |
| C3 | 11,507 | 7,712 | 19,219 | 1 / 0 | 123초 |

- 합계 39.1천 토큰, 단가 입력 $2·출력 $10(100만 토큰당, 제3자 집계 값, OpenAI 페이지 미확인)으로 약 $0.22
- 규모 추정 [계산]: dev_001은 752자이고 eval 평균은 560자다. 문서 길이를 그대로 적용하면 360회에 약 2.6M 토큰, $15이다. 적용하지 않으면 약 3.5M 토큰, $20이다. 동시 4개면 약 1.4~1.9시간이다. C3가 가장 비싸다(분석기 후보가 프롬프트에 들어가 입력이 김)
- 이 점검의 처분·지표는 dev 문서 1개라 결과로 쓰지 않는다

## 중간 결과 확인 (2026-10-21, 사전 계획과 다름)

반복 1회(120회, 네 조건 × 30개 문서)를 마친 뒤 사용자 요청으로 중간 결과를 봤다. 처음에는 완료 뒤에만 보기로 정했었다. 보기 전에 결과와 관계없이 남은 240회를 끝까지 돌리기로 정했고(사용자 결정), 중단 판정은 360회 결과로만 한다. 중간 값은 실행 폴더 밖에서 계산했고 `summary.json`은 쓰지 않았다.

- 반복 1회 기준: C0 몰래 정함 172/174토큰. C1·C2·C3는 모두 몰래 정함 0/174, 근거 없는 확정 0, 근거 채택 151/151, 보류 후보 적중 163/174였다. 중간 판정은 `stop`(C1 합격)으로 나왔다
- 이 값은 보고용 결과가 아니다. 최종 결과는 360회로 낸다

## 보류 (2026-10-21)

120/360회(반복 1회)에서 `--max-runs`로 멈춘 상태로 보류한다(사용자 결정). 실행 폴더 `results/exp002/eval/20261021T001807Z`는 그대로 두고 커밋하지 않는다. 보류 중에 단계 1.5(서비스화) 브랜치를 병합해 패키지 소스가 바뀌었다. 그래프·채점·집계 코드는 바뀌지 않았으므로 결과에는 영향이 없지만, 재개하면 그 세션 기록에 소스 해시 경고가 남는다(ADR-016). 재개 명령: `LANGSMITH_TRACING=false uv run tashkeel exp002 --split eval --resume --workers 4 --yes`.

- 2026-10-21 이후: 반복 1회에서 C1~C3가 모두 만점이었던 것을 시험지가 쉬운 탓으로 보고, 어려운 시험지와 99% 기준으로 [EXP-003](EXP-003.md)을 만들어 실행했다(사용자 결정, ADR-017, 판정 `stop`). EXP-002의 사전 등록(합격선·판정)은 바꾸지 않았고, 남은 240회는 재개하지 않았다
- 같은 날 EXP-003 준비로 `graph.py`·`reconcile.py`·`runner.py`·`prompts.py`·`config.py`를 바꾸고, 실행 장치를 `experiments/harness.py`로 옮겼다. EXP-002는 지시문 p0·근거 검사 v1로 고정되고(`exp002.SPEC.configure`), 저장된 `plan.json`과 같은 계획이 나오며, 골든 테스트가 그대로다[확인]. 재개하면 소스 해시 경고가 남는다

## 판정 기준 (2026-10-20 사용자 확정, 실행 전 고정)

코드: `src/tashkeel_check/experiments/exp002.py`의 `PASS_BAR`·`judge`. 결과는 `summary.json`의 `verdict`, 조건 쌍 차이는 `comparisons`에 나온다.

- 합격선(세 기준 모두): 몰래 정함 비율(`hidden_pick_rate`, 말없이 찍음 + 근거 없는 확정) ≤ 0.10, 근거 없는 확정 비율 ≤ 0.02, 근거 채택 검증 통과율 ≥ 0.90. eval 30개 × 3회를 합친 비율
- **중단:** C1(지시만)이 합격 → "지시만으로 충분". 단독 제품 대신 공개 벤치마크·연구 산출물로 마무리
- **합격:** C1 불합격이고, C2나 C3가 합격하며, C1이 못 넘은 기준마다 C1 − 그 조건 차이의 95% 구간(같은 문서를 함께 뽑는 문서 단위 부트스트랩 1,000회)이 그 조건이 나은 쪽에서 0을 넘음 → 단계 2로
- **불합격:** 그 밖. 프롬프트 재설계 또는 단계 3 멀티 에이전트 검토
- C0는 판정에 쓰지 않고 Q1 결과로 보고한다
- 기준값은 외부 근거가 없는 판단값이다(고객 인터뷰 불가, ADR-008). 결과 보고에도 그렇게 적는다

## 실행 명령

연습 모드로 배선만 확인(개발 문서, LLM 호출 없음):

```bash
uv run tashkeel exp002 --split dev --fake --repeats 1
```

실제 실행(비용 발생, 동의 필요). 끊어 가며 진행한다:

```bash
uv run tashkeel exp002 --split eval --workers 4 --max-runs 8 --yes   # 처음 8회로 사용량 확인
uv run tashkeel exp002-status                                         # 진행·토큰·예상 총량(결과 지표 없음)
uv run tashkeel exp002 --resume --workers 4 --max-runs 120 --yes     # 최근 실행을 이어서(반복 1회 = 120회)
touch results/exp002/eval/<시각>/STOP                                 # 돌던 실행만 마치고 멈춤
```

- 종료 코드 4는 중간 정지다. 출력된 `--resume` 명령으로 이어서 한다. API 오류로 멈추면 원인을 확인하고 재개한다. 429가 반복되면 `--workers`를 낮춘다
- `PRICE_INPUT_PER_MTOK`·`PRICE_OUTPUT_PER_MTOK`를 설정하면 진행 로그와 상태에 추정 금액이 같이 나온다
- LangSmith 키가 거부되면(401) 추적 오류가 stderr에 쌓이므로 `LANGSMITH_TRACING=false`로 돌린다

결과: `results/exp002/<split>/<시각>/`에 `plan.json`, `runs.jsonl`, 다 끝나면 `summary.json`이 생긴다. 실행별 산출물은 같은 폴더 아래 `조건/문서/r회차/`에 둔다

## 결과

없음(보류). 반복 1회의 중간 값은 위 "중간 결과 확인"에 있고 보고용 결과가 아니다. 결과는 "합성 문서 기준"으로만 보고하고 실제 서류의 오류율·포착률로 일반화하지 않는다.
